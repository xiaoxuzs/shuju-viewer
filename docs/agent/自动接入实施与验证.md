## 运行配置：默认关闭新增权限

不要直接对现有 `.env` 运行修改后的 main。启动仍会 bootstrap；本轮 DDL 只在测试库执行。
没有生产迁移、发布或服务重启授权。

- `AGENT_SOURCE_READ_ENABLED`：默认 false，研究模型读取脱敏源码的显式许可。
- `AGENT_IMPLEMENTATION_SOURCE_EVIDENCE_ENABLED`：默认 false，含源码研究材料转交实施模型的独立许可。
- `AGENT_PUBLIC_DOCUMENTS_JSON`：默认 `{}`，管理员提供 document ID → 固定公开 HTTPS URL，不是搜索引擎。
- `AGENT_INPUT_SNAPSHOT_ENABLED`：默认 false；启用后保留完整输入并检查内容变化。默认源码输入额度为 2 GiB，可显式配置。
- `AGENT_API_WORKER_ENABLED`：保留旧默认 true。启用应用验证/自动交付必须改为 false，并运行 `python -m app.agent_import.worker_main`。
- `AGENT_CANDIDATE_VERIFICATION_ENABLED`：默认 false；还需 PostgreSQL bin、Node、浏览器缓存、oracle root 和签名 key 的明确配置。
- `AGENT_INTERNAL_TOKEN`：新增特权模式要求本机连接和至少32字符的 token；不是全站登录/RBAC。前端 token 只存当前浏览器 session。
- `AGENT_AUTO_DELIVERY_ENABLED`：默认 false；不改变已有 Case 的 manual 策略。新请求显式 `delivery_policy=auto_test` 才进入自动分支。
- 自动模式仅接受 `VIEWER_ENV=test`、显式本机 `viewer_test_*` PostgreSQL、受限 role、输入保留和验证器；必须从 `SourceSnapshot.export` 的源码副本运行，`VIEWER_BUILD_ID`、source-manifest、实际模块根和文件哈希一致。可编辑 checkout 不获得自动发布权限。

可信启动器先导出工作区快照，再从该副本启动 API/独立 Worker；`AGENT_SOURCE_ROOT` 指向同一副本。
`SourceSnapshot` 和 Windows Job Object 都**不是**文件/网络隔离沙箱。

保护的 oracle 文件名为 `<source-content-sha256>-<requirements-sha256>.json`。
后一个哈希来自真实 Case 请求和用户消息，不由模型选择。当前 `AcceptanceContract` 只支持最多100条
Bottom-Up match 的完整独立预期值，并声明必需视图的最低可用状态。没有基线、必需视图缺失或旧证据均阻止交付；不把 preview 冒充正式范围验证。

自动分支：`READY_FOR_REVIEW` 释放租约 → 新 Worker 认领 → `DELIVERING` → 重查签据/输入/代码 →
事务内导入和生成正式 MD artifact → `SUCCESS`。人工模式仍须显式审批，但默认 importer 也在提交前锁定/复查 Case，取消或版本冲突使导入回滚。
验证开启时，MD 在数据库 artifact 中提交，可通过 `/agent-import-cases/<id>/handover` 下载；不是聊天拼接。
