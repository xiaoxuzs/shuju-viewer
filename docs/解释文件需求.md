# `prsm.js` 文件需求

本文只说明 `prsm.js` 文件本身需要哪些内容。每个字段都按“字段名：是什么。用于什么/为什么需要。”的格式说明。

`prsm.js` 的基本入口应为：

```js
prsm_data = {
  "prsm": {
    ...
  }
};
```

## 版本一：当前查看器使用的 `prsm.js`

当前查看器的 MS1/MS2 原始谱图来自 TopFD 的 `spectrum*.js`，所以 `prsm.js` 不需要保存完整原始谱峰数组，但必须保存谱图定位信息、去卷积峰、匹配离子、序列注释、切割位点和 mass shift。

### 1. 顶层结构

- `prsm_data`：`prsm.js` 的入口变量。后端解析文件时从这里读取整条 PrSM 数据。
- `prsm`：单条 PrSM 的主体对象。用于承载摘要、谱头、匹配峰和蛋白注释等所有详情内容。

### 2. `prsm` 顶层摘要字段

- `prsm_id`：PrSM 的业务编号，如 `1`、`2509`。用于详情页 URL、列表跳转和定位对应的 `prsm*.js` 文件。
- `p_value`：PrSM 的 p-value 统计显著性指标。用于页面展示鉴定可信度。
- `e_value`：PrSM 的 e-value 统计显著性指标。用于列表排序和判断结果可靠性。
- `fdr`：PrSM 的 false discovery rate 或 q-value。用于展示假阳性控制信息。
- `matched_fragment_number`：匹配到的理论碎片离子数量。用于 summary 和结果质量判断。
- `matched_peak_number`：匹配到的实验峰数量。用于 summary 和结果质量判断。

### 3. `prsm.ms.ms_header`

- `spectrum_file_name`：原始谱图文件名，如某个 `.mzML` 文件名。用于追溯该 PrSM 来自哪个实验谱图文件。
- `ms1_ids`：TopFD 导出的 MS1 谱图 id。当前前端取第一个 id 去请求 `topfd/ms1_json/spectrum{id}.js`。
- `ms1_scans`：MS1 在原始谱图文件中的 scan 号。用于页面显示 MS1 scan 信息。
- `ids`：TopFD 导出的 MS2 谱图 id。当前前端把它作为 MS2 id 去请求 `topfd/ms2_json/spectrum{id}.js`。
- `scans`：MS2 在原始谱图文件中的 scan 号。用于页面显示 MS2 scan 信息，也用于 full 导入时写入真实 scan。
- `precursor_mono_mass`：前体单同位素质量。用于 summary 中展示 precursor mass。
- `precursor_charge`：前体电荷数。用于 summary、MS1 前体标记和匹配解释。
- `precursor_mz`：前体 m/z。用于 summary 和 MS1 图中的 precursor marker。
- `feature_inte`：feature 强度或前体相关强度。用于展示该 PrSM 对应 feature 的强度信息。

### 4. `prsm.ms.peaks.peak[]`

- `peak[]`：去卷积峰列表，每个元素是一条 TopFD/TopPIC 解释后的峰。用于匹配峰表格、MS2 标注和 fragmentation 视图。
- `spec_id`：该 peak 所属的谱图 id。用于把 peak 关联回对应 MS2 谱图。
- `peak_id`：去卷积峰编号。用于和 MS2 `spectrum*.js` 里的 `envelopes[].id` 对齐，从而打开局部 isotope envelope 视图。
- `monoisotopic_mass`：去卷积后的中性单同位素质量。用于 matched peaks 表格和理论质量误差计算展示。
- `monoisotopic_mz`：该去卷积峰对应的 m/z。用于把 matched ion 叠加到 MS2 原始谱图上。
- `intensity`：该去卷积峰强度。用于 matched peaks 表格、MS2 matched ion 柱高和局部图强度展示。
- `charge`：该去卷积峰电荷。用于 matched peaks 表格和 isotope envelope 匹配。
- `matched_ions`：该 peak 匹配到的理论离子集合。用于判断该 peak 是否高亮，以及显示离子标签和误差信息。

### 5. `matched_ions.matched_ion[]`

- `matched_ion[]`：一个 peak 上匹配到的理论离子列表。用于支持一个实验峰对应一个或多个离子解释。
- `ion_type`：离子类型，如 `B`、`Y`、`C`、`Z_DOT`。用于区分 N 端离子和 C 端离子，并决定序列图和谱图标签。
- `match_shift`：匹配时使用的质量偏移。用于说明该离子是否带有 mass shift 相关匹配。
- `theoretical_mass`：理论碎片离子质量。用于 matched peaks 表格中和实验质量对比。
- `ion_position`：离子在 proteoform 序列中的位置。用于计算或展示该离子对应的切割位置。
- `ion_display_position`：页面显示用的离子位置。用于 MS2 标签、局部图标签和 matched peaks 表格。
- `ion_sort_name`：离子排序或标识名称。用于前端生成稳定行 key 和排序显示。
- `ion_left_position`：离子左边界位置。用于 fragment/sequence 相关视图中定位离子覆盖范围。
- `mass_error`：实验质量与理论质量的差值。用于 matched peaks 表格展示匹配误差。
- `ppm`：质量误差的 ppm 表示。用于 matched peaks 表格和 hover 信息中展示匹配精度。

### 6. `prsm.annotated_protein`

- `annotated_protein`：该 PrSM 对应的蛋白和 proteoform 注释对象。用于 sequence coverage、proteoform 信息和修饰显示。
- `sequence_id`：来源软件中的 protein/sequence 编号。用于把 PrSM 关联到对应 protein。
- `proteoform_id`：来源软件中的 proteoform 编号。用于把 PrSM 关联到对应 proteoform。
- `sequence_name`：蛋白名称或 accession。用于详情页标题、描述和结果追溯。
- `sequence_description`：蛋白描述文本。用于详情页展示更完整的蛋白说明。
- `proteoform_mass`：该 proteoform 的质量。用于 sequence coverage 顶部展示和质量对照。
- `n_acetylation`：N 端乙酰化标记。用于说明该 proteoform 是否带有 N 端乙酰化。
- `unexpected_shift_number`：unexpected mass shift 数量。用于详情页展示该 proteoform 中未知质量偏移数量。
- `annotation`：序列、切割位点和 mass shift 的详细注释。用于渲染 sequence coverage 和 fragmentation 视图。

### 7. `annotated_protein.annotation`

- `protein_length`：蛋白或 proteoform 序列长度。用于 sequence coverage 计算显示范围和行数。
- `first_residue_position`：当前 proteoform 在序列中的起始位置，通常为 0-based。用于画起始边界符号和判断灰色未覆盖区域。
- `last_residue_position`：当前 proteoform 在序列中的结束位置，通常为 0-based。用于画结束边界符号和判断灰色未覆盖区域。
- `annotated_seq`：带修饰标记的序列字符串。用于保留来源软件中的注释序列表达。
- `residue[]`：逐个氨基酸列表。用于 sequence coverage 中逐字绘制蛋白序列。
- `cleavage[]`：逐个切割位点列表。用于 sequence coverage 中绘制 N/C 端离子命中的切割标记。
- `mass_shift[]` 或 `mass_shift`：修饰或质量偏移列表。用于 sequence coverage 中绘制彩色背景和修饰文字。

### 8. `residue[]`

- `position`：氨基酸在序列中的 0-based 位置。用于把氨基酸、切割位点和 mass shift 放到正确坐标。
- `acid`：氨基酸单字母，如 `A`、`M`、`K`。用于 sequence coverage 中显示具体氨基酸字符。

### 9. `cleavage[]`

- `position`：切割位置，表示两个 residue 之间的断裂点。用于在 sequence coverage 中定位切割标记。
- `exist_n_ion`：该切割位是否存在 N 端离子命中，通常为 `"1"` 或 `"0"`。用于决定是否画 N 端方向的切割线。
- `exist_c_ion`：该切割位是否存在 C 端离子命中，通常为 `"1"` 或 `"0"`。用于决定是否画 C 端方向的切割线。
- `matched_peaks`：该切割位关联的 matched peaks。用于把序列切割位点和谱图峰关联起来。

### 10. `cleavage[].matched_peaks.matched_peak[]`

- `matched_peak[]`：某个切割位点关联到的匹配峰列表。用于说明这个切割位由哪些实验峰支持。
- `ion_type`：该 matched peak 对应的离子类型。用于判断是 N 端离子还是 C 端离子。
- `ion_position`：离子在序列中的位置。用于关联切割点和离子位置。
- `ion_display_position`：页面显示的离子位置。用于 sequence tooltip 或其它显示。
- `spec_id`：该 matched peak 所属谱图 id。用于关联回对应 MS2。
- `peak_id`：该 matched peak 对应的去卷积峰 id。用于和 `ms.peaks.peak[].peak_id` 对齐。
- `peak_charge`：该 matched peak 的电荷。用于显示峰解释信息。

### 11. `mass_shift[]`

- `id`：mass shift 编号。用于区分多个修饰或质量偏移。
- `left_position`：mass shift 起始位置。用于在 sequence coverage 中确定背景色起点。
- `right_position`：mass shift 结束位置。用于在 sequence coverage 中确定背景色终点。
- `shift`：质量偏移数值。用于说明该区域发生了多少 Da 的质量变化。
- `anno`：修饰或质量偏移的显示文字。用于 sequence coverage 上方的修饰注释。
- `shift_type`：mass shift 类型，如 `fixed`、`variable`、`unexpected`。用于决定显示颜色和修饰语义。

## 版本二：内存读取 mzML 作为 MS1/MS2 谱图时的 `prsm.js`

如果 MS1/MS2 原始谱图改为后端从 mzML 内存读取，`prsm.js` 仍然不能只保存 scan。mzML 只能提供原始谱峰、RT、MS level、precursor 等谱图层信息，不能提供 PrSM 的鉴定解释层信息。

所以 mzML 版本的 `prsm.js` 仍然必须保留版本一中的 PrSM 解释字段，并额外补充 mzML 谱图定位和 envelope 信息。

### 1. 仍然必须保留的字段

- `prsm_id`：PrSM 的业务编号。mzML 不提供 PrSM 编号，所以仍需由 `prsm.js` 保存。
- `p_value`：PrSM 的 p-value。mzML 不提供鉴定显著性，所以仍需由 `prsm.js` 保存。
- `e_value`：PrSM 的 e-value。mzML 不提供搜索结果排序指标，所以仍需由 `prsm.js` 保存。
- `fdr`：PrSM 的 FDR/q-value。mzML 不提供假阳性控制信息，所以仍需由 `prsm.js` 保存。
- `matched_fragment_number`：匹配碎片数。mzML 不知道理论离子匹配结果，所以仍需由 `prsm.js` 保存。
- `matched_peak_number`：匹配峰数。mzML 不知道哪些峰被鉴定结果解释，所以仍需由 `prsm.js` 保存。
- `ms.peaks.peak[]`：去卷积匹配峰列表。mzML 原始峰不是去卷积峰，所以仍需由 `prsm.js` 保存。
- `matched_ions.matched_ion[]`：理论离子匹配信息。mzML 不包含理论碎片离子、误差和 ppm，所以仍需由 `prsm.js` 保存。
- `annotated_protein`：蛋白和 proteoform 注释。mzML 不包含蛋白序列和 proteoform 信息，所以仍需由 `prsm.js` 保存。
- `annotation.residue[]`：氨基酸序列列表。mzML 不包含蛋白序列，所以仍需由 `prsm.js` 保存。
- `annotation.cleavage[]`：切割位点列表。mzML 不包含离子覆盖切割信息，所以仍需由 `prsm.js` 保存。
- `annotation.mass_shift[]`：质量偏移或修饰列表。mzML 不包含该 PrSM 的 proteoform 修饰解释，所以仍需由 `prsm.js` 保存。

### 2. `ms.ms_header` 在 mzML 版本中的字段

- `spectrum_file_name`：该 PrSM 对应的 mzML 文件名。用于确认从哪个 mzML 内存索引中查找谱图。
- `ms1_scans`：该 PrSM 对应的 MS1 scan 号。用于从 mzML 内存索引中找到默认 MS1 谱图并在页面展示。
- `scans`：该 PrSM 对应的 MS2 scan 号。用于从 mzML 内存索引中找到默认 MS2 谱图并在页面展示。
- `ms1_ids`：兼容当前接口的 MS1 id 字段。可继续保留，用于不改前端或兼容旧逻辑。
- `ids`：兼容当前接口的 MS2 id 字段。可继续保留，用于不改前端或兼容旧逻辑。
- `precursor_mono_mass`：PrSM 鉴定使用的前体单同位素质量。用于 summary 展示，不能完全依赖 mzML selected ion 替代。
- `precursor_charge`：PrSM 鉴定使用的前体电荷。用于 summary、MS1 marker 和匹配解释。
- `precursor_mz`：PrSM 鉴定使用的前体 m/z。用于 summary 和 MS1 图中的 precursor marker。
- `feature_inte`：该 PrSM 对应 feature 强度。用于展示鉴定结果关联的强度信息。

### 3. mzML 版本建议新增的 `spectrum_map`

建议在 `prsm.js` 中新增：

```json
"spectrum_map": {
  "source_type": "mzml",
  "mzml_file": "file.mzML",
  "default_ms1_scan": 161,
  "default_ms2_scan": 197,
  "all_ms1_scans": [161],
  "all_ms2_scans": [197],
  "ms1_native_id": "controllerType=0 controllerNumber=1 scan=161",
  "ms2_native_id": "controllerType=0 controllerNumber=1 scan=197"
}
```

- `source_type`：谱图来源类型，如 `mzml`。用于告诉后端这条 PrSM 的谱图不再来自 TopFD `spectrum*.js`。
- `mzml_file`：mzML 文件名或路径。用于定位应该使用哪一个已加载到内存的 mzML 文件。
- `default_ms1_scan`：默认显示的 MS1 scan。用于打开详情页时直接找到 MS1 谱图。
- `default_ms2_scan`：默认显示的 MS2 scan。用于打开详情页时直接找到 MS2 谱图。
- `all_ms1_scans`：该 PrSM 相关的全部 MS1 scan。用于未来支持多个 MS1 scan 切换。
- `all_ms2_scans`：该 PrSM 相关的全部 MS2 scan。用于未来支持多个 MS2 scan 切换。
- `ms1_native_id`：mzML 中 MS1 的原生 spectrum id。用于 scan 号不稳定或不唯一时精确定位谱图。
- `ms2_native_id`：mzML 中 MS2 的原生 spectrum id。用于 scan 号不稳定或不唯一时精确定位谱图。

### 4. mzML 版本中 `ms.peaks.peak[]` 仍然必须存在

- `peak_id`：去卷积峰编号。用于和 envelope id 对齐，即使原始谱峰来自 mzML 也不能删除。
- `monoisotopic_mass`：去卷积后的中性单同位素质量。用于 matched peaks 表格和误差展示，mzML 原始峰不能替代它。
- `monoisotopic_mz`：去卷积峰对应的 m/z。用于在 mzML 原始 MS2 谱图上寻找并标注 matched ion。
- `intensity`：去卷积峰强度。用于 matched ion 高亮和表格展示。
- `charge`：去卷积峰电荷。用于解释峰和匹配 envelope。
- `matched_ions`：该去卷积峰匹配到的理论离子。用于显示红色离子标签、ppm 和理论质量。

### 5. mzML 版本建议新增的 `envelopes[]`

如果不再读取 TopFD `topfd/ms2_json/spectrum*.js`，但仍要保留当前点击 matched peak 后的局部 isotope envelope 视图，`prsm.js` 或它直接关联的解释结构必须补充 `envelopes[]`。

推荐结构：

```json
"envelopes": [
  {
    "id": 0,
    "mono_mass": 9255.9901,
    "charge": 10,
    "env_peaks": [
      { "mz": 925.6, "intensity": 1000.0 }
    ]
  }
]
```

- `envelopes[]`：MS2 去卷积 envelope 列表。用于局部 isotope cluster 视图。
- `id`：envelope 编号。必须和 `ms.peaks.peak[].peak_id` 对齐，用于点击 matched peak 后找到对应 isotope cluster。
- `mono_mass`：该 envelope 对应的单同位素质量。用于和去卷积 peak 进行质量对齐。
- `charge`：该 envelope 的电荷。用于判断 envelope 是否对应当前 matched peak。
- `env_peaks[]`：该 envelope 中的同位素峰列表。用于在局部图中画空心圆 isotope peaks。
- `env_peaks[].mz`：同位素子峰的 m/z。用于局部图 X 轴定位。
- `env_peaks[].intensity`：同位素子峰强度。用于局部图 Y 轴高度。

### 6. mzML 版本中不需要放进 `prsm.js` 的内容

- `MS1 原始峰数组`：mzML 内存读取已经能提供 MS1 原始峰。放进每个 `prsm.js` 会造成大量重复。
- `MS2 原始峰数组`：mzML 内存读取已经能提供 MS2 原始峰。放进每个 `prsm.js` 会造成文件巨大且难维护。
- `完整 profile 谱图数据`：这属于原始谱图层，应由 mzML 提供，不应重复塞进 PrSM 解释文件。

## 两个版本的区别

- 当前版本：`ms1_ids` 和 `ids` 用于定位 TopFD `spectrum*.js`。`prsm.js` 保存鉴定解释，TopFD `spectrum*.js` 保存原始谱峰和 envelopes。
- mzML 内存版本：`spectrum_map`、`scan` 或 `native_id` 用于定位 mzML 内存谱图。`prsm.js` 仍保存鉴定解释；如果不再读取 TopFD `spectrum*.js`，还必须补充 `envelopes[]`。
- 共同点：两个版本都必须保留 `ms.peaks.peak[]`、`matched_ions`、`annotated_protein`、`residue[]`、`cleavage[]` 和 `mass_shift[]`，因为这些是 PrSM 解释信息，mzML 原始谱图不能替代。

一句话总结：`mzML` 只能替代 MS1/MS2 原始谱峰来源，不能替代 `prsm.js` 中的 PrSM 解释信息；如果想保持当前查看器完整形态，`prsm.js` 必须继续提供去卷积峰、匹配离子、序列注释、切割位点和 mass shift，mzML 版本还要额外提供 scan/native id 映射和 envelope 信息。
