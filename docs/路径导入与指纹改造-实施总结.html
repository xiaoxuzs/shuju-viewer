路径导入与元数据指纹

Viewer 后端 / 前端 / 数据库 / 测验 — 实施总结（验收通过）

低耦合 · 三模块拆分 · 指纹 < 0.5s 目标可测

本文档说明本轮已落地的改造范围，便于归档与交接。图示均为内嵌 SVG，可离线打开。

一、目标与结果概览

  • 去掉 ZIP 上传：导入改为仅接受服务器磁盘路径，后台解析 TopPIC 数据集根后入库。
  • 重复识别：使用元数据 manifest MD5（每文件 相对路径|size|mtime，排序后整体 MD5），与 MD5-demo/fast_metadata_hash.py 语义一致，不读文件内容。
  • 嵌套目录：用户可选外层文件夹，由 resolve_ingest_root 自动定位唯一 ingest 根。
  • 模块化：指纹、根路径解析、导入编排职责分离；性能测验放在仓库 cs/ 目录。
  • 测验：back/tests/ 单元测试全绿；cs/指纹性能测验.py 本地改路径直接运行，你已确认测试合格。

二、新增与调整的后端模块

路径作用
back/app/fingerprint/数据集元数据指纹计算（scandir、排除规则、MD5）。
back/app/dataset_ingest_root/从用户所选路径解析 TopPIC ingest 根（topfd / toppic_* 等）。
back/app/services/import_jobs.pyZIP 逻辑已移除；run_path_import_job：指纹 → plan → ingest → finalize 写指纹列。
back/app/api/v1/imports.pyPOST /imports 接收 JSON（ImportEnqueueIn）。
back/app/core/config.py可选 IMPORT_PATH_MUST_BE_UNDER_DATA_ROOT 限制路径必须在数据根下。

六、主流程（作业阶段）

  1. fingerprint：解析 ingest 根 → 计算元数据指纹 → 库内查重（冲突则 job 失败）。
  2. plan：plan_zip_ingest 布局检测。
  3. ingest：ingest_universal_toppic / ingest_universal_prsm_js。
  4. finalize：写入 source_root、source_dataset_fingerprint、spectra 能力及 mzML 映射（与原先 finalize 语义对齐，无目录 rename）。
