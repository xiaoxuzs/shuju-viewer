1. 系统概览

backFastAPI + SQLAlchemy + PostgreSQL（universal 七表），手写 text() SQL； ZIP 导入、TopPIC/TopFD 树解析、可选 mzML 内存谱图。

frontVite + React 18 + React Router + TanStack Query + Tailwind； 路由形态 /datasets/:slug/:cutoff/...，PrSM 详情支持 TopFD JS 与 mzML 两种谱源。

4. 核心数据流（端到端）

  1. 导入：POST /imports → 临时 ZIP → SHA256 去重 → 后台线程解压至 *.incoming → plan_zip_ingest → DB 写入 → 成功后目录 rename，并更新 source_root、detail_path 前缀、capabilities.spectra_source、runs.run_metadata.mzml_file_path（如适用）。
  2. 列表：cutoff 由 identification_matches.extra_metadata.source_cutoff 过滤；排序字段白名单防注入。
  3. PrSM 详情：库表字段 + 磁盘 PrSM 文件合并；谱图按 spectra_source 走 MS1/MS2 JS API 或 mzML scan API。

5. 实现亮点

  • ZIP zip-slip 校验与并行解压设计到位。
  • 导入 先 DB 再换目录，Windows rename 失败时有降级与路径修正逻辑。
  • mzML 导入期不读全文，映射来自 PrSM header，与产品约束一致。
  • 前端 PrSM 页对 双谱源、dataset 能力刷新、zoom 状态拆分处理细致。
  • parse.ts 对 TopPIC 单元素数组与两种谱 JSON 形状的处理是前后端契约的关键。

6. 待完善项（按维度）

数据与迁移

  • 部分 DDL 依赖启动时执行，建议 Alembic 等版本化迁移作为单一事实来源。
  • 大量 jsonb_extract_path_text 重复，可收敛为常量或小查询层。

任务与进程

  • 导入为 daemon 线程，与多 worker、进程重启、资源隔离不匹配长期运维；宜独立 worker / 队列。

性能与内存

  • MzmlStore 整文件进内存 + LRU 按 run 个数；大 mzML 仍有峰值与首请求阻塞风险。
  • 列表 SQL 在数据量增大时可能需要表达式索引或生成列评审。

安全与配额

  • 无认证；上传无全局大小/并发上限（依赖环境与磁盘）。
  • 生产环境应收紧 CORS、覆盖默认数据库连接串。

测试与前端工程

  • 后端 API / ingest 集成测试偏少；前端无 Vitest/E2E。
  • 导入轮询无 AbortController；部分列表页未统一 error UI。
  • 蛋白质列表行使用 window.location 整页跳转，与 SPA 不一致。
文档一致性：空状态里的 CLI 示例若仍写 --mode full，与当前适配器「仅支持 fast」不一致，建议改为 --mode fast 或删除该参数说明。

7. 建议改进顺序（精简路线图）

优先级项
1修正 CLI / 空状态文案与真实支持参数一致
2引入数据库迁移工具，替代仅启动时 DDL
3导入任务脱离 API 进程（队列或子进程）+ 上传限额
4观测：结构化日志、关键阶段耗时；mzML 加载可配置与限流
5测试：pytest 覆盖 API + fixture ZIP；Vitest 覆盖 parse.ts 等
6前端：Router 导航、列表错误态、导入取消与 Error Boundary
