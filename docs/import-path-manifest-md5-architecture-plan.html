1 设计原则与模块边界

低耦合

模块间仅通过窄接口传递纯数据（路径、选项、指纹结果、查询回调），不在路由或编排层内联哈希与递归遍历实现。

单一职责

指纹计算、路径导入编排、能力测试三者代码分离；算法变更集中在指纹模块，用测试模块锁住行为。

实施时需避免的耦合

  • 在 FastAPI 路由内实现 MD5 或全盘扫描。
  • 在指纹模块内执行 SQL 或调用 ingest。
  • 能力测试默认依赖生产库写权限（应对 fixture / 临时库）。

2 删除清单（旧概念）

以下从代码与 schema 中移除，不再保留 ZIP 上传与 SHA256 分支。

类别删除内容
HTTP UploadFile、临时 ZIP、sha256_hex_of_file、ZIP 扩展名校验、基于 ZIP 的 409。
Runner ZIP 解压、zipfile 并行解压、临时文件 unlink。
数据库 source_zip_sha256、uq_datasets_source_zip_sha256；import_jobs.source_zip_name 等 ZIP 语义字段。
服务 ZIP 专用指纹工具、find_dataset_with_zip_sha256 及仅服务该列的迁移。
产品 「上传 ZIP」文案与控件 → 改为服务器路径输入或受控选择。

4 数据集级 Manifest MD5 规范（契约）

由 dataset_manifest_md5 实现并单测锁定；path_import 只消费指纹字符串。

规则摘要

  • 根目录 ingest_root 与当前 planner 使用的根一致。
  • 仅常规文件；符号链接策略在实现中写死并由测试覆盖。
  • 每行：<relpath>\t<file_md5_hex>\n；source_dataset_md5 = md5(M.encode("utf-8")).hexdigest()。
  • 零文件：建议拒绝导入；大文件：流式哈希。

5 数据库变更

  • import_jobs：去掉 source_zip_name；新增 source_path；可选 manifest_md5_hex 便于排障。
  • 同步更新 docs/universal_schema.sql 与启动迁移逻辑。

6 API 与导入作业编排

请求体包含 source_path、slug、name 等；同步阶段不扫全树算 MD5；返回 202 + job_id。

7 能力测试模块（独立）

运行时间

对 fixture 或环境变量指定目录测量 fingerprint 阶段墙钟时间；可多次运行取中位数，结果输出表格或 JSON。

精确性

Golden manifest / 期望 MD5；覆盖排序、排除规则、改一字节应改变哈希等用例。

推荐 pytest 无 DB、无网络默认跑；与「真 ingest + 临时库」集成测试分层。

8 建议实施顺序与验收

#交付物验收
1dataset_manifest_md5 + 单测 + golden算法与第 4 节一致
2DB 迁移 + universal_schema.sql无 ZIP 列；新索引生效
3path_import + 删 ZIP API/runner仅路径；作业含查重
4能力测试入口 + fixture一条命令可复现报告
5前端与对外说明无上传 ZIP；错误语义清晰

风险提示

Manifest 排除范围若与 planner 认定的数据文件不一致，可能导致「指纹一致但无法 ingest」或相反；建议增加一条对齐 planner 的集成 fixture。
