XIC 色谱曲线 — M / M+1 / M+2 叠加规划

在 Bottom-Up 鉴定详情页的 Extracted Ion Chromatogram（XIC） 上， 除现有单条 M（单同位素前体）曲线外，叠加 M+1 与 M+2 同位素提取曲线。 本文档为实施前规划，含定义、方法、改动清单与浏览器内效果模拟；确认后再编码。

范围：BU 鉴定详情 · XIC 待确认：m/z 计算精度 向后兼容 API 扩展 生成日期：2026-06-02

1背景与目标

现状：鉴定详情页 XIC 仅在鉴定给出的 precursor_mz ± ppm 窗口内，沿 RT 提取 MS1 最强峰强度，绘制单条蓝色曲线（见 BuXicChart.tsx + xic_service.py）。

目标：同一 RT 轴上叠加三条曲线 — M、M+1、M+2 — 帮助判断前体同位素包络是否与肽段序列/电荷一致，并识别共洗脱干扰。

不在本次范围（除非您另行指定）：整体页 TIC/BPC、Top-Down PrSM 局部 envelope、LC-MS 3D 热图、Bruker .d run（当前 D10 仍返回 unsupported_raw_format）。

2M / M+1 / M+2 定义

标签 含义 m/z 目标（电荷 z） 典型相对强度* 色谱形状
M 单同位素前体峰（全轻同位素组成，如全 12C） 鉴定结果中的 precursor_mz（已有） 100%（基准） 与肽段洗脱一致，RT apex 对齐
M+1 质量比 M 大 1 Da 的同位素峰（主要来自 13C、15N 等 +1 中子） 由肽段序列 + 电荷 理论计算；一阶近似：M + 1.003355 / z 约 5%–40%（随肽段碳原子数增加） 与 M 同 RT 轮廓，峰值按比例降低
M+2 质量比 M 大 2 Da 的同位素峰（两个 13C，或 34S、18O 等组合） 理论计算；一阶近似：M + 2.006710 / z（双 13C 主导时） 约 1%–15% 与 M 同 RT；长肽更明显

* 相对强度为天然丰度下的典型量级，实际随序列元素组成变化；图中模拟采用示意比例 M : M+1 : M+2 ≈ 1 : 0.32 : 0.09。

与 MS1 谱图的关系

MS1 某一 RT 帧上，前体在 m/z 轴呈间隔约 1/z Th 的同位素簇；XIC 则是对每个同位素 m/z 分别在全 RT 范围做 extracted ion，得到三条时间-强度色谱。三条曲线应共用 RT 轴、apex 与 DIA-NN RT 窗口阴影。

3实现方法

3.1 总体数据流

match（sequence, charge, precursor_mz） → theoretical_precursor_isotopes → xic_service 三次提取 / 一次遍历 → BuXicOut 扩展 → BuXicChart 三线叠加

3.2 后端：理论 m/z（推荐独立小模块）

新建 back/app/bu/services/theoretical_precursor_isotopes.py（与 theoretical_fragments.py 并列，仅用 pyteomics，不依赖 FastAPI）：

def precursor_isotope_targets(
    sequence: str,
    charge: int,
    monoisotopic_mz: float,
) -> list[tuple[str, float]]:
    """
    返回 [("M", mz0), ("M+1", mz1), ("M+2", mz2)]。
    优先：pyteomics.mass 按序列算同位素质量再 / charge；
    回退：monoisotopic_mz + k * 1.003355 / charge（k=0,1,2）。
    """

推荐精度：用序列 composition 计算 M+1、M+2 的准确质量再除以 z，与 b/y 模块一致依赖 pyteomics；鉴定 precursor_mz 仍作为 M 的锚点（可校验 |Δ| < 若干 ppm，超差仍用鉴定值并记日志）。

3.3 后端：XIC 提取（扩展 xic_service.py）

在现有 MS1 遍历逻辑上，对每个 scan 分别对三个 target m/z 做 ±ppm 窗口 argmax(intensity)：

for spec in ms1_scans_in_rt_window:
    rt.append(spec_rt)
    for label, target_mz in targets:
        mz_tol = target_mz * ppm * 1e-6
        best = max peak in window
        series[label].append(best)

性能：与现逻辑同阶（每 scan 多 2 次窗口扫描）；RT 窗口已限制在 apex ±5 min，可接受。可选：单次 zip 遍历 mz/intensity 同时更新三个 best。

3.4 API 契约扩展（向后兼容）

扩展 BuXicOut，保留原字段 intensity = M 曲线：

{
  "rt": [ ... ],
  "intensity": [ ... ],           // M，与现网一致
  "intensity_m1": [ ... ],        // 新增，可为 null（旧客户端忽略）
  "intensity_m2": [ ... ],
  "isotope_targets": [
    { "label": "M",   "target_mz": 477.3051 },
    { "label": "M+1", "target_mz": 477.8068 },
    { "label": "M+2", "target_mz": 478.3085 }
  ],
  "precursor_mz": 477.3051,
  "ppm": 10,
  "rt_apex": ..., "rt_start": ..., "rt_stop": ...,
  "unit_rt": "min"
}

端点不变：GET /api/v1/datasets/{slug}/matches/{match_id}/xic?ppm=10。
