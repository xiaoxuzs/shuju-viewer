Bottom-Up（BU）数据导入与识别条件

DIA-NN 2.0 · 路径导入 · 目录布局 · 谱图与报告匹配规则

analysis_mode = BOTTOM_UP · DatasetShape.DIANN_DIA

本文说明 Viewer 在什么情况下能将一套数据正确识别为 Bottom-Up（BU）数据集并完成导入。 实现入口：back/app/dataset_ingest_root/resolver.py、 back/app/services/import_planner/planner.py、 back/app/ingest/bu/universal_diann_adapter.py。 可离线用浏览器直接打开本 HTML。

一、导入方式（不是浏览器上传单文件）

重要：BU 数据通过服务器磁盘路径导入，不是把 .parquet / .mzML / .d 等文件上传到浏览器。

  • 前端 Datasets 页 → Import from folder → 填写或浏览选择文件夹绝对路径
  • API：POST /api/v1/imports，JSON 体含 source_path、slug、name
  • 本地开发可用 POST /api/v1/imports/pick-folder 打开原生文件夹选择对话框（需配置开启）
方式是否支持说明
填写 / 选择文件夹路径✅ 支持后端进程必须能访问该路径
浏览器上传单个数据文件❌ 不支持v1 无 multipart 文件上传入口
上传 ZIP 后自动解压导入❌ 不专门支持需先解压，再指向解压后的目录

路径基本要求：必须存在且为目录。若环境变量 IMPORT_PATH_MUST_BE_UNDER_DATA_ROOT=true，路径还须在配置的 DATA_ROOT 之下。

二、能被识别为 BU 的目录条件

核心函数 has_bu_diann_layout(path) 要求同时满足下列 A、B 两类条件。

A. DIA-NN 报告（二选一，文件名必须精确）

在目录树中递归搜索 *.parquet，其中文件名必须是：

  • all_report.parquet（优先使用）
  • target_report.parquet（若无 all_report 则回退）

其他 parquet（如 all_lib.parquet、target_lib.parquet）不能作为识别依据。文件须为 DIA-NN 2.0 生成的有效 parquet，能被 PyArrow 正常读取。

B. 至少一种原始谱图

  • 存在 *.mzML 或 *.mzml 文件，或
  • 存在名为 *.d 的目录（Bruker timsTOF 原始数据）

C. ingest 根解析规则

情况行为
所选路径本身满足 A + B直接作为 ingest 根
所选路径不满足，但恰好一个直接子目录满足自动下钻到该子目录
多个子目录同时满足报错：Multiple dataset folders found
同一根目录既有 TopPIC 布局又有 BU 布局报错：matches both TopPIC and DIA-NN
完全找不到合法布局报错：Could not find a TopPIC or DIA-NN dataset folder

三、推荐的目录结构

3.1 扁平混放（实测可用）

<ingest_root>/
├── 20200110_Hela_500ng_DIA_25cm_120min_R1.mzML    # Thermo DIA 单文件
├── DC2817_ELB00124_DIA_..._13560.d/               # Bruker .d 目录
└── DIANN_2.0/
    └── DIANN_2.0/
        ├── all_report.parquet                      # 必需
        ├── target_report.parquet                   # 可选（精炼版）
        ├── all_report.stats.tsv                    # 可选 → QC 卡片
        └── all_report.protein_description.tsv      # 可选 → 蛋白注释

3.2 规范化子目录（同样支持）

<ingest_root>/
├── diann/
│   ├── all_report.parquet
│   ├── all_report.stats.tsv
│   └── all_report.protein_description.tsv
└── spectra/
    ├── sample_A.mzML
    └── sample_B.d/

两种布局均可被 resolver 识别；元数据指纹对整个 ingest 根目录做 manifest MD5。

四、各文件角色一览

文件 / 目录导入阶段说明
all_report.parquet / target_report.parquet✅ 必需主鉴定报告；写入 identification_matches 等
all_report.stats.tsv✅ 可选与报告同 stem 的旁文件；写入 datasets.extra_metadata
all_report.protein_description.tsv✅ 可选蛋白描述注释
*.mzML / *.mzml✅ 登记 runMS2 / XIC / TIC 等按需读盘
有效 *.d/ 目录✅ 登记 runTIC / BPC / DIA windows 等；match 级 MS2/XIC 对 .d 有限制
*.pkl❌ 忽略v1 不入库
*_matrix.tsv、all_lib.parquet 等❌ v1 忽略定量矩阵 / 谱图库，二期再考虑

五、Bruker .d 目录的有效条件

.d 本质是文件夹（仪器导出时目录名即以 .d 结尾），不是像 mzML 那样的单文件。

有效 TDF 根须同时满足：

  • analysis.tdf 存在且文件大小 > 0
  • 同目录存在 analysis.tdf_bin

5.1 双层嵌套（zip 解压后常见）

xxx.d/                              ← 外层（analysis.tdf 可能为 0 字节空文件）
└── xxx.d/                          ← 内层，真实数据
    ├── analysis.tdf                (非空)
    ├── analysis.tdf_bin
    ├── chromatography-data.sqlite
    └── ...

run_discovery.py 会自动下钻：若外层 analysis.tdf 无效，但存在唯一同名子目录 xxx.d/xxx.d/ 且内层有效，则使用内层路径登记 run。

六、DIA-NN 报告行过滤规则

导入时默认只写入满足以下条件的鉴定行（Q_VALUE_CUTOFF = 0.01）：

  • Q.Value < 0.01
  • Decoy = 0（非诱饵肽）

parquet 需包含 DIA-NN 2.0 标准列，如 Run、Precursor.Id、Modified.Sequence、Stripped.Sequence、Precursor.Charge、Precursor.Mz、Protein.Ids、RT、Q.Value 等（见 diann_parquet_reader.REPORT_COLUMNS）。

七、Run 名称与谱图文件匹配

DIA-NN 报告 Run 列中的值，必须与目录内发现的谱图文件能够对应：

场景规则
多个 mzML / 多个 .d每个 Run 必须能匹配到某个谱图文件名（经规范化：去路径、去 .mzML / .d 后缀、大小写不敏感）
仅发现一个谱图 run允许单 run 回退：即使 Run 名称不完全一致，也映射到该唯一文件
目录含 mzML（mzml_memory 或 mixed）导入前额外执行 mzML 映射校验；失败报 DIA-NN mzML mapping validation failed
仅含有效 .d（tdf_memory）跳过 mzML 映射校验，但仍需 Run 与 .d 目录名匹配（或单 run 回退）

八、会被拒绝的常见情况

场景结果
只有 parquet，没有 mzML / .d布局识别失败
只有 mzML / .d，没有 all_report.parquet 或 target_report.parquet布局识别失败
同一目录既有 TopPIC 标志（topfd、toppic_*_cutoff 等）又有 DIA-NN 报告歧义报错
多个子目录都符合 BU 布局报错，需整理为单一 ingest 根
相同元数据指纹的数据集已导入重复拒绝（409 / job failed）
目录下 0 个可统计文件拒绝导入
parquet 损坏或关键列缺失导入 job 失败
多 run 时 Run 与谱图文件名对不上导入 job 失败
.d 目录无有效 analysis.tdf + analysis.tdf_bin该 .d 被跳过；若最终无有效 run 则失败

九、PFMB 预计算注释（可选，非基础 BU 必需）

results.pfmb + index.json 用于详情页「Pre-computed PFMB annotation」能力，不是 BU 基础导入的必需文件。

导入方式PFMB 行为
Web 路径导入（POST /imports）当前不会自动挂载 PFMB（未传 pfmb_sidecar_dir）
CLI：ingest_universal_diann --pfmb-sidecar-dir <dir>目录内须同时存在 results.pfmb 与 index.json

无 PFMB 时数据集仍可正常导入；capabilities.has_ms2_pfmb = false，详情页使用实时 MS2 注释而非预计算 PFMB。

十、导入前快速自检清单

  1. 选择的是文件夹路径，且后端进程能访问（非浏览器本机路径与服务端路径混淆）
  2. 目录树内存在 all_report.parquet 或 target_report.parquet
  3. 同目录树内至少有 1 个 *.mzML 或 1 个有效 *.d/
  4. 同一 ingest 根下没有 TopPIC 标志目录与 BU 报告混放
  5. parquet 来自 DIA-NN 2.0，Run 列与谱图文件名一致（或仅单 run 可回退）
  6. 该数据目录未曾以相同元数据指纹导入过
  7. （可选）需要 PFMB 时，使用 CLI 并指定含 results.pfmb + index.json 的 sidecar 目录
