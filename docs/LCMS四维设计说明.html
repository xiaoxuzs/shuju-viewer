1. 质谱与 LC-MS 是什么

质谱（Mass Spectrometry, MS）测量的是：样品里有哪些离子、它们的质量电荷比 m/z 是多少、以及信号有多强 Intensity。

液相色谱（LC）在进质谱之前，按时间把混合物「洗」出来：不同化合物在不同保留时间 RT 到达检测器。

合在一起就是 LC-MS：横轴是时间（RT），每个时刻拍一张「质谱照片」——上面很多峰，每个峰是一个 m/z 和强度。

2. 三维（3D）在说什么

在 LC-MS 语境里，常说的 「3D」 不是数学里的抽象三维空间，而是把下面三个量放在一起看：

维度符号含义单位（常见）
保留时间RT化合物何时从色谱柱流出秒 (s) 或分钟
质荷比m/z离子的质量/电荷Th 或 Da（常写作 m/z）
强度Intensity检测器信号强弱计数或相对强度

3D 数据逻辑（与你白板上半部分一致）：

Scan → RT (s) → m/z + intensity

每一个 Scan（扫描） 对应质谱仪在某一时刻的一次测量；这次测量有一个 RT，内部包含成千上万个 (m/z, intensity) 点。

把很多个 Scan 叠在一起，就得到一张 RT × m/z 的「地形图」，高度是 intensity——Viewer 里 LC-MS 3D 图就是把这张图用 Three.js 点云画出来（X=RT，Y=m/z，Z=强度）。

3. 四维（4D）多出来的一维是什么

离子淌度（Ion Mobility, IM）：在离子进入质谱分析之前（或同时），按它们在气体中的迁移能力再分一层。结构相近、m/z 相近的离子，RT 和 m/z 可能很像，但「形状/碰撞截面」不同，在 IM 维上可以分开。

仪器类型举例：TIMS（捕集离子淌度）、FAIMS、漂移管 IM 等。数据文件常见扩展：LC-IM-MS 或 timsTOF 等产生的 mzML。

因此 4D 在 LC-MS 领域通常指四个测量轴：

#维度说明
1RT色谱时间（与 3D 相同）
2IM离子淌度，常用 1/K₀（V·s/cm²）或漂移时间（ms）
3m/z质荷比（与 3D 相同）
4Intensity强度（与 3D 相同）

3D 和 4D 的关键区别（必读）

  • 3D：在同一个 RT，质谱仪通常只给你一张谱（一个 Scan → 一组 m/z/int）。
  • 4D：在同一个 RT，仪器会快速拍很多张谱，每张对应一个 slightly 不同的 IM（例如 IM=1.5、1.6、1.7…）。这一组谱在白板上叫做一个 frame（帧）。

类比（帮助记忆）：

  • 3D 像在一间教室里，按上课时间（RT）拍照，每节课只有一张照片（一张谱）。
  • 4D 像在同一节课里，用不同滤镜（IM）连拍了很多张；这一整组照片是一个 frame；每张里仍有很多像素点 (m/z, intensity)。

4. 与你白板图的对应关系

命名注意（写代码时）：Viewer 现有代码里的 SpectrumFrame 表示「一条 scan 的谱」，不是白板里的 frame。4D 设计里建议：

  • 白板 frame → 代码名 RtFrame（某一 RT 下的 scan 集合）
  • 白板 scan + IM → 代码名 MobilityScan

6.2 从 mzML 到 frame 的规则（概念）

  1. 解析每条 spectrum 时读出 IM 值（如 inverse reduced ion mobility 或 drift time）及单位。
  2. 将 RT 相近（容差 ε，如 0.01 s）的 MS1 scan 归为同一个 RtFrame；若文件自带 frame 编号则优先用厂商字段。
  3. frame 内按 IM 从小到大排序。

6.4 3D 与 4D 的关系

3D 可视为 4D 的退化：每个 RtFrame 里只有 1 条 MobilityScan（或无 IM）时，退化为现在的 LC-MS 3D。49 数据集（TopFD）无离子淌度，继续走 3D 路径即可。

7. 界面与交互设想（对齐业内常见流程）

主流 LC-IMS-MS / TIMS 分析软件（如 mzMine、各类厂商工作台）普遍采用多块联动视图，而非单张四维直角坐标图。核心是：在选定 LC 时刻（frame）后，用二维热图展示 m/z × IM（强度着色）；再用XIC（RT–强度）定位在时间轴上，用 Mobilogram（IM–强度）或窄质量窗切片观察淌度轮廓；需要时再打开固定 RT+IM 下的 MS1 / MS2 条带谱。

参考：mzMine — Ion mobility data visualisation；LC-MS 与 LC-IMS-MS 对比：mzMine — LC-MS and LC-IMS-MS comparison。

Viewer 采纳的缺省交互顺序：

  1. XIC（上）——拖移或点击时间轴 → 选定当前 frame 对应 RT。
  2. Frame heatmap（中左，主画面）——纵轴 IM、横轴 m/z；十字线对齐前体或点击位置。
  3. Mobilogram（中右上）——在光标 m/z（或前体窗口）下的强度–IM 曲线。
  4. Single spectrum（右下）——当前 RT + 选中 IM 的 MS1（m/z–强度）。

补充：可保留可选的 WebGL 三维点云（RT×IM×m/z）用于全局浏览；优先级低于上述「热图 + 迹线」组合，与常见教程/文献配图一致。

9. API 与数据结构草案

与 §8 对齐的实现建议：一次应答可下发「工作台包」——例如 xic_rt / xic_i（窄 m/z 窗）、当前 frame 的 heatmap_im / heatmap_mz / heatmap_i（二维矩阵 + 坐标轴刻度）、以及在光标 m/z 下的 mobilogram（IM–I）与选定 IM 下的 ms1（m/z–I，已降采样）。亦可用单一的 points（RT/IM/m/z/I）由前端聚合成上述四类视图。

主接口：GET /api/v1/datasets/{id}/runs/{run_id}/lcms-4d

{
  "dimensionality": 4,
  "axes": {
    "x": { "key": "rt_seconds", "label": "RT" },
    "y": { "key": "im", "label": "1/K0" },
    "z": { "key": "mz", "label": "m/z" },
    "w": { "key": "intensity", "label": "Intensity", "scale": "log" }
  },
  "points": { "rt": [], "im": [], "mz": [], "intensity": [], "scan": [] },
  "frames": [
    { "frameIndex": 0, "rtSeconds": 123.45, "scanCount": 200, "imMin": 0.85, "imMax": 1.55 }
  ],
  "meta": { "rtFrameCount": 12, "returnedPointCount": 45000, "generatedMs": 120 }
}

分箱：在 (RT, IM, m/z) 三维网格上做 max intensity 聚合，再按强度取 top-N 点，避免一次传全量原始峰。

可选后续接口：

  • .../lcms-4d/frames/{index}/scans — 某一 frame 下各 IM 的轮廓
  • .../lcms-4d/slice?axis=im&value=1.5 — 固定 IM 切一片，形状与 3D API 兼容便于对照
