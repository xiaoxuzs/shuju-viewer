## 2. 基本原则（硬性约束）

1. **原始谱图不入库**：数据库只存 `runs.file_path` 与鉴定元数据；峰数组运行时从磁盘读取。  
2. **鉴定索引入库**：`identification_matches` 必须含足够字段定位谱图（RT、precursor_mz、charge、run_id；可选 scan/native_id 写入 `extra_metadata`）。  
3. **按页取数**：整体页禁止为单条 match 预拉 MS2；详情页禁止拉全 run 全 scan 列表回前端。  
4. **懒加载 + 缓存**：mzML 按 `dataset_id` + `run_id` 进程内索引；`.d` 按 run 打开句柄，帧/色谱按需计算。  
5. **复用不修改**：BU 可读 Top-Down 的 `spectrum_memory` / `get_mzml_spectrum`，但**不得修改**其源码；BU 专用逻辑放在 `back/app/bu/`。  
6. **DTO 统一**：凡「m/z–强度棍状图」对外统一 §7 的 `SpectrumV1` 形状，前端 `BuSpectrumChart` 只认这一种。  
7. **路径导入**：`datasets.source_root` 为谱图根；API 解析路径时必须校验文件存在，禁止 zip-slip 式越界。

## 3. 数据分层：图从哪来

```text
┌─────────────────────────────────────────────────────────────┐
│ L0 磁盘原始文件（真值，只读）                                   │
│   mzML: 逐 scan 的 m/z[]、intensity[]、MS level、precursor    │
│   .d:   analysis.tdf + analysis.tdf_bin，经 tdfpy 读帧/窗口   │
└────────────────────────────┬────────────────────────────────┘
                             │ 运行时读取
┌────────────────────────────▼────────────────────────────────┐
│ L1 数据库索引（导入时写入）                                     │
│   identification_matches: RT, mz, charge, q_value, run_id     │
│   runs: file_path, run_metadata.raw_format                    │
└────────────────────────────┬────────────────────────────────┘
                             │ 详情页请求时
┌────────────────────────────▼────────────────────────────────┐
│ L2 API 计算层（按需）                                          │
│   色谱聚合、XIC 提取、理论 b/y、scan 匹配、Sequence coverage   │
└────────────────────────────┬────────────────────────────────┘
                             │ JSON
┌────────────────────────────▼────────────────────────────────┐
│ L3 前端渲染（BuSpectrumChart、XICChart、TicChart 等）          │
└─────────────────────────────────────────────────────────────┘
```

| 层级 | 存什么 | 不存什么 |
|---|---|---|
| L0 | 全部原始峰 | — |
| L1 | 鉴定行 + 文件路径 | 完整 mzML 内容、全 TIC 数组 |
| L2 | 响应当次请求的计算结果 | 跨请求持久化峰数组（除内存缓存） |

## 4. 查看路径：用户怎么看到图

### 4.1 整体页加载顺序（Bottom-Up）

```text
用户打开 /datasets/:slug
  → GET /api/v1/datasets/{slug}          （analysis_mode、runs、capabilities）
  → GET /api/v1/datasets/{slug}/overview （QC 数字，可无谱图）
  → 用户选择 run_id（默认第一个 mzML 或列表首项）
  → GET .../runs/{run_id}/chromatogram?type=tic|bpc
  → [可选] GET .../runs/{run_id}/dia-windows        （仅 raw_format=bruker_d）
  → [可选] GET .../overview/rt-mz                   （DB 聚合，二期）
```

**禁止**：整体页 mount 时请求 `.../matches/{id}/spectrum/*`。

### 4.2 鉴定详情页加载顺序

```text
用户从 Matches 表点击 match_id
  → 进入 /datasets/:slug/matches/:matchId
  → GET /api/v1/datasets/{slug}/matches/{matchId}     （摘要，无大数组）
  → 并行：
       GET .../matches/{matchId}/xic
       GET .../matches/{matchId}/spectrum/ms2         （含 matched_ions）
       GET .../matches/{matchId}/spectrum/ms1
  → [若 run 为 bruker_d] GET .../matches/{matchId}/mobility-slice?rt=&mz=
```

**顺序建议**：先摘要 → 再 XIC + MS2（MS2 为核心）→ MS1 → 4D 可选。

### 4.3 蛋白详情页

```text
GET /api/v1/datasets/{slug}/proteins/{proteinId}
  → 返回 sequence、coverage_segments[]、peptides 列表
  → 不调用 chromatogram / spectrum API
```

## 6. 各图产生算法与 API 契约

### G1 — QC 统计卡片（非棍状谱图，但属整体页）

| 项 | 约定 |
|---|---|
| **产生** | 导入时读 `all_report.stats.tsv` 写入 `datasets.extra_metadata.stats`；`overview` 读入后输出 `qc.by_run`；数字卡片另可从 DB `COUNT(*)` 聚合 |
| **查看** | 整体页顶部，无 run 参数 |
| **API** | `GET /api/v1/datasets/{slug}/overview` |
| **响应字段** | `precursors_identified`, `proteins_identified`, `median_mass_acc_ms1`, `median_mass_acc_ms2`, `fwhm_rt`, … |

---

### G2 — TIC（Total Ion Chromatogram）

| 项 | 约定 |
|---|---|
| **定义** | 每个时间点（RT）上，该 scan 所有峰强度之和 |
| **mzML 产生** | 遍历 `ms level == 1` 的 scan；`tic[i] = sum(intensity[])`；`rt[i]` 来自 `scan start time`（统一为 **分钟**） |
| **.d 产生** | `tdfpy`：遍历 `dia.ms1` 帧；每帧 `centroid(min_peaks=2)` 后对 intensity 列求和；`rt = frame.time / 60` |
| **查看** | 整体页；用户切换 `run_id` 后重新请求 |
| **API** | `GET /api/v1/datasets/{slug}/runs/{run_id}/chromatogram?type=tic` |
| **响应** | `{ "type": "tic", "unit_rt": "min", "rt": number[], "intensity": number[] }` |
| **参考** | `demo_01_mzml_overview.py`、`plot_spectra.py` 图 1 |

**约束**：

- 默认最多返回 **全 run** 点；若 run 过长，后端可按最大 8000 点**等距降采样**，并在响应加 `"downsampled": true`。  
- 前端 Y 轴可格式化为 K/M/G，与 demo 一致。

---

### G3 — BPC（Base Peak Chromatogram）

| 项 | 约定 |
|---|---|
| **定义** | 每个 RT 上强度最高的那个峰的强度 |
| **产生** | 同 G2，但 `bpc[i] = max(intensity[])`（无峰则为 0） |
| **API** | `.../chromatogram?type=bpc` |
| **响应** | 同 G2 结构，`type: "bpc"` |
| **参考** | demo01 图 2、`plot_spectra.py` 图 2 |

---

### G4 — RT–m/z 简图（可选 v1）

| 项 | 约定 |
|---|---|
| **定义** | 二维密度：X=RT，Y=precursor m/z，颜色=鉴定条数 |
| **产生** | SQL / pandas 对 `identification_matches` 按 RT、m/z 分箱计数；**不读 mzML** |
| **查看** | 整体页可选区块 |
| **API** | `GET /api/v1/datasets/{slug}/overview/rt-mz` |
| **响应** | `{ "bins_rt": [...], "bins_mz": [...], "counts": [[...]] }` 或 hexbin 点列表 |
| **参考** | `demo_03` 图 5（正式站为简化版，非全屏） |

---

### G5 — DIA 隔离窗口图（仅 `raw_format=bruker_d`）

| 项 | 约定 |
|---|---|
| **定义** | 每个隔离窗口的 m/z 中心与宽度（水平条带） |
| **产生** | `tdfpy`：`dia.windows` 按 `isolation_mz` 去重；每条 `{ mz, width }` |
| **查看** | 整体页；仅当选中 run 为 `.d` 时显示，否则**不请求、不占位** |
| **API** | `GET /api/v1/datasets/{slug}/runs/{run_id}/dia-windows` |
| **响应** | `{ "windows": [{ "mz": number, "width": number, "label": string }] }` |
| **参考** | `plot_spectra.py` 图 5 |

---

### G6 — XIC（Extracted Ion Chromatogram）

| 项 | 约定 |
|---|---|
| **定义** | 固定 precursor m/z ± ppm 容差，沿 RT 提取 MS1 各帧该窗口内最强峰强度 |
| **产生** | 输入：`precursor_mz`、`ppm_tol`（默认 **10**）、`rt_lo`、`rt_hi`（来自 match 的 RT.Start/Stop ± 扩展，默认 ±5 min）<br>遍历 MS1 scan；`mz_window = prec_mz * ppm * 1e-6`；取窗口内 `argmax(intensity)` |
| **叠加** | 响应含 DIA-NN：`rt_apex`, `rt_start`, `rt_stop` 供前端画阴影与竖线 |
| **查看** | **仅鉴定详情页** |
| **API** | `GET /api/v1/datasets/{slug}/matches/{match_id}/xic?ppm=10` |
| **响应** | `{ "rt": [], "intensity": [], "precursor_mz", "ppm", "rt_apex", "rt_start", "rt_stop", "unit_rt": "min" }` |
| **参考** | `demo_05_xic.py` |

**约束**：

- XIC **必须**使用鉴定所在 `run_id` 的 mzML，禁止跨 run。  
- 若 RT 窗口内无 MS1 点，返回 200 + 空数组，前端显示「无信号」。

---

### G7 — MS2 + b/y 标注（核心）

| 项 | 约定 |
|---|---|
| **定义** | 一条 MS2 scan 的 m/z–强度棍状图 + 理论 b/y 离子匹配高亮 |
| **产生步骤** | 见 [§10](#10-ms2-scan-定位规则鉴定谱图) 定位 scan → 读 mzML MS2 → `pyteomics.mass` 算 b/y（charge 1,2）→ ±ppm 匹配实验峰 |
| **查看** | **仅鉴定详情页** |
| **API** | `GET /api/v1/datasets/{slug}/matches/{match_id}/spectrum/ms2?ppm=20` |
| **响应** | `SpectrumV1` + `matched_ions: [{ ion_type, position, charge, theo_mz, exp_mz, ppm, intensity }]` |
| **参考** | `demo_04_precursor_to_ms2.py` |

**约束**：

- 理论碎片只使用 `Stripped.Sequence`（无修饰质量扩展 v1 不做 PTM 偏移）。  
- 一实验峰只保留一个最佳匹配（按强度优先去重）。  
- 颜色约定：`b` → 蓝，`y` → 红（前端默认，可配置但不得与 Top-Down 组件混用）。

---

| **参考** | demo01 图 3（逻辑类似，但 RT 由鉴定约束） |

### G9 — m/z × 1/K₀ 小窗（仅 .d）

### G10 — Sequence coverage（序列图，非质谱）

## 7. 统一谱图 DTO

所有「棍状谱图」（G7、G8）及 mzML 原始 scan 抽取结果，对外统一为：

```json
{
  "scan": 67726,
  "native_id": "controllerType=0 controllerNumber=1 scan=67726",
  "ms_level": 2,
  "rt_seconds": 5547.6,
  "rt_minutes": 92.46,
  "mz": [300.1, 301.2],
  "intensity": [1000, 2000],
  "precursor": {
    "selected_mz": 477.3051,
    "charge": 2,
    "isolation_target_mz": 478.0,
    "isolation_lower": 6.5,
    "isolation_upper": 6.5
  },
  "matched_ions": []
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `mz` | `number[]` | ✅ | 与 `intensity` 等长 |
| `intensity` | `number[]` | ✅ | 非负 |
| `ms_level` | `1 \| 2` | ✅ | |
| `rt_minutes` | `number` | ✅ | 前端轴标签统一用分钟 |
| `matched_ions` | `array` | MS2 必填 | MS1 可为 `[]` |
| `precursor` | `object \| null` | MS2 推荐 | |

**前端**：`BuSpectrumChart` 只接受上述结构；禁止直接解析 mzML XML。

## 8. 缓存与性能策略

| 资源 | 策略 | 失效 |
|---|---|---|
| mzML 索引 | 复用 `spectrum_memory`：按 `dataset_id` 载入，LRU 驱逐 | 进程重启；`release_dataset` |
| .d 句柄 | 每 `run_id` 一个 `tdfpy` 会话，LRU ≤2 runs | 同上 |
| TIC/BPC | 可缓存于 run 级，键 `(run_id, type)`，TTL 或进程内 | 文件 mtime 变化 |
| XIC | **不缓存**全 run；可按 `(match_id, ppm)` 短缓存 | 可选 |
| MS2 单 scan | 不持久缓存；依赖 mzML 索引 O(1) 取 scan | — |

**禁止**：

- 一次性把整份 mzML 的 TIC/XIC 数组塞进 `identification_matches.detail_cache`。  
- 详情页一次请求返回 &gt;2MB JSON（必要时 MS2 峰降采样并标注 `"peak_count_original"`）。

| 场景 | 使用哪个 run |
|---|---|


或

```json

  "tdf_path": "D:\\dia-shuju\\DC2817_....d\\DC2817_....d"
}
```

## 10. MS2 scan 定位规则（鉴定→谱图）

当 `extra_metadata` 无可靠 `scan_number` 时，后端**必须**按以下顺序定位 MS2（与 demo_04 一致）：

```text
1. 读取 match：precursor_mz, rt_apex (RT), rt_start, rt_stop
2. 在对应 run 的 mzML 中遍历 ms_level == 2 的 scan
3. 过滤：|scan_rt_min - rt_apex| <= 0.5 min
4. 过滤：isolation_window 包含 precursor_mz
         lo = target_mz - lower_offset
         hi = target_mz + upper_offset
         要求 lo <= precursor_mz <= hi
5. 在候选中取 |scan_rt - rt_apex| 最小者
6. 将 scan_number 写入响应，并可选回写 extra_metadata 供下次加速
```

若步骤 5 无候选 → `404` + `{ "error": "ms2_scan_not_found", "match_id", "rt_apex", "precursor_mz" }`。

**禁止**：用随机 MS2 或固定 scan 代替。
