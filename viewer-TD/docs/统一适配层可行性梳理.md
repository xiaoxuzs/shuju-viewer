## 术语

| 术语 | 含义 |
|------|------|
| **解释文件（viewer 契约）** | `data/prsms/prsm{id}.json` — viewer-TD 入库与详情 API 消费的 PrSM 详情 |
| **PFMB** | Peak Fragment Match **Bundle**；引擎主产物 **`results.pfmb`**（二进制，见 `DEVELOPER_PFMB.md`） |
| **prsm.cache** | `ingest` 阶段产出的统一输入缓存（TopPIC js / xml+msalign 等归一化） |
| **统一适配层** | viewer-TD 导入编排：识别形态 → 调用 PFMB → **egress JSON** → 组装 viewer 解释文件 → 现有 ingest |
| **egress** | `pfmb_bridge.exe egress` — 从 `results.pfmb` 导出联调/下游用 JSON（**非**直接等于 viewer 解释文件） |

**PFMB 参考文档**（均在 `viewer-TD/PFMB/`）：

| 文档 | 用途 |
|------|------|
| [`PFMB_BRIDGE_EXE.md`](../PFMB/PFMB_BRIDGE_EXE.md) | `ingest` / `run` / `egress` 命令与参数 |
| [`DEVELOPER_PFMB.md`](../PFMB/DEVELOPER_PFMB.md) | `.pfmb` 二进制布局；`PfmbReader` |
| [`pfmb_io.py`](../PFMB/pfmb_io.py) | Python 读 bundle；`export_pfmb_prsm_to_json` |

## 1. 结论

| 问题 | 结论 |
|------|------|
| 形态 A（已有 `prsm*`） | **直接入库**，不跑 PFMB |
| 形态 B（xzx_PXD045330 类，无 `data/`） | **ingest → run → egress → 组装 `prsm*.json` → 入库** |
| 引擎主结果存什么？ | **`results.pfmb`（二进制）** — 权威匹配结果 |
| viewer 磁盘解释文件？ | **`prsm{id}.json`** — 由 cache + egress 组装，兼容现有 API |
| 前端要改吗？ | **不用改读 pfmb**；仍消费后端 JSON API |
| 后端能否直读 `.pfmb`？ | **可以**（`pfmb_io.PfmbReader`），可作为二期优化；**一期以 egress + 组装 json 入库** |

## 2. 做什么 / 不做什么

### 做

- TopPIC 形态 **A**、**B** 路径导入
- 形态 B：对接 **`pfmb_bridge.exe`** 全流程
- **JSON 导出设计**（§6）：egress 层 + viewer 解释层
- `toppic_admission`：编排 PFMB 子进程、staging、组装、校验
- 形态 B 入库形态：**`PRSM_BUNDLE` + `mzml_memory`**

### 不做

- DIA-NN `pos.pkl` 接入 viewer-TD（PFMB bridge 支持，但 **viewer-TD 本阶段不做 BU**）
- 浏览器直接解析 `.pfmb`
- 用 egress 的 `prsm{N}_peaks.json` **直接**当 viewer 解释文件（缺 annotated_protein / ms_header 等，须组装）

## 4. PFMB 三阶段流程（形态 B）

与 [`PFMB_BRIDGE_EXE.md`](../PFMB/PFMB_BRIDGE_EXE.md) 一致；staging 建议：`shuju/adapted/<job_id>/`。

```text
work/
├── prsm.cache                 ← ingest 产出
├── cache_build.manifest.json  ← ingest 可选 manifest
├── engine_out/
│   ├── results.pfmb           ← run 产出（二进制主结果）
│   └── summary.json
└── egress/
    ├── _index.json            ← egress --all
    └── prsm{N}_peaks.json     ← 每条 PRSM 峰-碎片匹配 JSON
```

### 4.1 ingest（接入数据）

**330 类（形态 B）**：

```powershell
pfmb_bridge.exe ingest `
  --source xml_msalign `
  --prsm-xml "<ingest_root>/toppic/*_toppic_prsm.xml" `
  --ms2-msalign "<ingest_root>/topfd/*_ms2.msalign" `
  --cache ".\work\prsm.cache" `
  --manifest ".\work\cache_build.manifest.json"
```

**histone 类（形态 A 若将来重跑引擎）** — 本阶段 viewer 不默认触发：

```powershell
pfmb_bridge.exe ingest --source toppic_js --prsm-dir ".../data_js/prsms" --cache ".\work\prsm.cache"
```

### 4.2 run（引擎）

```powershell
pfmb_bridge.exe run `
  --cache ".\work\prsm.cache" `
  --output ".\work\engine_out" `
  --preset native_coverage `
  --rebuild-frag-cache
```

产出：**`results.pfmb`** + `summary.json`。

### 4.3 egress（导出 JSON，联调 / 组装输入）

单条：

```powershell
pfmb_bridge.exe egress `
  --cache ".\work\prsm.cache" `
  --pfmb ".\work\engine_out\results.pfmb" `
  --prsm 0 `
  --format json `
  --out ".\work\egress\prsm0_peaks.json"
```

全量：

```powershell
pfmb_bridge.exe egress `
  --cache ".\work\prsm.cache" `
  --pfmb ".\work\engine_out\results.pfmb" `
  --all --format json `
  --out-dir ".\work\egress"
```

bridge 日志为**单行 JSON**（`ok` / `interface` / `output` 等），便于 `import_jobs` 解析。

### 4.4 viewer 组装（适配层第 4 步，§6.3）

egress 只含**峰-碎片匹配**；viewer 还需要 TopPIC 注释与谱头。由 **`toppic_admission.assemble_prsm_json`** 合并：

- `prsm.cache`（ingest 时的蛋白/序列/scan/统计量）
- `prsm{N}_peaks.json`（PFMB 匹配）
- mzML 路径（`spectrum_map`）

输出：**`<staging>/data/prsms/prsm{id}.json`**

```text
用户选择目录
  ↓
resolve_ingest_root
  ↓
toppic_admission.detect
```

**拒绝**：仅 mzML；缺 xml 或 msalign；PFMB 子进程非零退出。

## 6. JSON 导出格式设计

分三层：**索引** → **PFMB egress 峰匹配** → **viewer 解释文件**。

### 6.1 `_index.json`（egress 全量索引）

由 `egress --all` 产出，供适配层批量组装与 job 进度统计。

```json
{
  "format": "pfmb_egress_index_v1",
  "generated_at": "2026-05-28T12:00:00Z",
  "cache_path": "work/prsm.cache",
  "pfmb_path": "work/engine_out/results.pfmb",
  "engine_summary_path": "work/engine_out/summary.json",
  "record_count": 42,
  "entries": [
    {
      "prsm_index": 0,
      "prsm_id": 1,
      "peaks_file": "prsm0_peaks.json",
      "scan": 197,
      "spec_id": 12,
      "match_count": 856,
      "peptide_preview": "MKALIVL..."
    }
  ]
}
```

| 字段 | 说明 |
|------|------|
| `prsm_index` | PFMB bundle 内顺序下标（egress `--prsm` 参数） |
| `prsm_id` | TopPIC 业务 id（文件名 `prsm{id}`）；与 cache 对齐，**可能与 index 不同** |
| `peaks_file` | 相对 `out-dir` 的路径 |

### 6.2 `prsm{N}_peaks.json`（PFMB egress 单条）

与 [`pfmb_io.py`](../PFMB/pfmb_io.py) 中 `PfmbRecord.matches` 字段对齐；**egress 输出以此为准**（若 bridge 已实现略有扩展，以实际 egress 样例覆盖本文）。

```json
{
  "format": "pfmb_egress_peaks_v1",
  "prsm_index": 0,
  "prsm_id": 1,
  "scan": 197,
  "spec_id": 12,
  "peptide": "MKALIVLTTTIAAMMLLK",
  "metadata": {},
  "summary": {
    "match_count": 856,
    "matched_peak_count": 120
  },
  "series_table": ["c", "z_dot", "b", "y"],
  "matches": [
    {
      "peak_id": 3,
      "fragment_series": "y",
      "fragment_ordinal": 5,
      "observed_neutral_mass": 612.334,
      "theoretical_neutral_mass": 612.331,
      "mass_error_ppm": 4.9,
      "mass_error_da": 0.003,
      "intensity": 1.2e6,
      "charge": 2
    }
  ]
}
```

| 字段 | 来源 | 用途 |
|------|------|------|
| `matches[]` | PFM2 列数据 + `series_table` | 组装 `ms.peaks.peak[].matched_ions` |
| `scan` / `spec_id` | PFM2 头 | 写入 `ms.ms_header`、mzML 定位 |
| `peptide` | PFM2 UTF-8 肽段 | 与 cache 中 `annotated_seq` 交叉校验 |

**注意**：此文件**不包含**完整 `annotated_protein.annotation`（residue/cleavage/mass_shift），须从 **`prsm.cache`** 读取。

### 6.3 `prsm{id}.json`（viewer 解释文件 — 适配层最终落盘）

**目标**：`load_prsm_document` → `get_prsm_root()` → 现有 PrSM API / `parse.ts` 可直接消费。  
语义基准：[`docs/解释文件需求.md`](../../docs/解释文件需求.md)（mzML 内存版）。

**推荐顶层**（与 TopPIC js 兼容）：

```json
{
  "prsm_data": {
    "prsm": {
      "prsm_id": "1",
      "p_value": "0.001",
      "e_value": "0.01",
      "fdr": "0.05",
      "matched_fragment_number": "856",
      "matched_peak_number": "120",
      "ms": {
        "ms_header": {
          "spectrum_file_name": "20191118_....mzML",
          "ms1_scans": "161",
          "scans": "197",
          "ms1_ids": "161",
          "ids": "197",
          "precursor_mono_mass": "12345.67",
          "precursor_charge": "10",
          "precursor_mz": "1234.567",
          "feature_inte": "1.5e8"
        },
        "peaks": {
          "peak": []
        }
      },
      "annotated_protein": {},
      "spectrum_map": {
        "source_type": "mzml",
        "mzml_file": "20191118_....mzML",
        "default_ms1_scan": 161,
        "default_ms2_scan": 197,
        "all_ms1_scans": [161],
        "all_ms2_scans": [197]
      }
    }
  },
  "viewer_provenance": {
    "format": "viewer_prsm_json_v1",
    "pfmb_path": "work/engine_out/results.pfmb",
    "egress_peaks_file": "work/egress/prsm0_peaks.json",
    "cache_path": "work/prsm.cache",
    "engine_preset": "native_coverage"
  }
}
```

#### 6.3.1 字段来源映射

| viewer 字段 | 来源 |
|-------------|------|
| `prsm_id`, `p_value`, `e_value`, `fdr` | **prsm.cache**（TopPIC xml/js  ingest） |
| `annotated_protein` 全树 | **prsm.cache** |
| `ms.ms_header` | **prsm.cache** 为主；`scan`/`spec_id` 与 peaks.json 校验 |
| `ms.peaks.peak[]` | **由 `matches[]` 按 `peak_id` 分组** 从 peaks.json 组装 |
| `peak[].matched_ions.matched_ion[]` | 每条 match → `ion_type`（series 大写化：`y`→`Y`）、`theoretical_mass`、`ppm`、`mass_error` |
| `peak[].monoisotopic_mass` / `intensity` / `charge` | match 的 observed 字段 |
| `spectrum_map` | staging 内 mzML 相对路径 + header scan |
| `viewer_provenance` | 适配层写入；**入库时可剥离**，不进入 DB |

#### 6.3.2 `matches` → `peak[]` 组装规则

```text
1. 对 prsm{N}_peaks.json.matches 按 peak_id 分组
2. 每组 → 一个 peak 对象：
     peak_id, spec_id, monoisotopic_mass ← observed_neutral_mass
     intensity, charge
     matched_ions.matched_ion[] ← 组内每条 match：
       ion_type ← map_series(fragment_series)   # y→Y, z_dot→Z_DOT
       theoretical_mass ← theoretical_neutral_mass
       mass_error ← mass_error_da
       ppm ← mass_error_ppm
       ion_position / ion_display_position ← fragment_ordinal（或 cache 补充）
3. matched_peak_number ← 分组数
4. matched_fragment_number ← len(matches)
```

cleavage / residue / mass_shift：**不**从 PFMB 重算，**整段取自 prsm.cache**（与 TopPIC 注释一致）。

#### 6.3.3 落盘约定

| 项 | 约定 |
|----|------|
| 路径 | `<staging>/data/prsms/prsm{id}.json` |
| 编码 | UTF-8 |
| `id` | TopPIC 业务 `prsm_id`，**不是** PFMB `prsm_index` |
| 索引 | `_index.json.entries[].prsm_id` 决定写哪些文件 |

### 6.4 读取路径对照

| 场景 | 方式 |
|------|------|
| **一期入库** | 组装好的 `prsm{id}.json` → `ingest_universal_prsm_js` |
| **联调/抽检** | `egress` → `prsm{N}_peaks.json`；或 `pfmb_io.PfmbReader` |
| **二期优化** | 详情 API 按需 `PfmbReader.read_by_prsm_index` + cache，跳过磁盘 json |
