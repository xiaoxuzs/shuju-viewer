# 维护与完整性检查

## 1. “完整”的定义

本目录满足以下条件时，才可以标记为完整：

1. 从 `main.tsx` 可达的谱图/色谱/热图/散点/序列/3D 组件均已登记。
2. 所有 `d3`、`three`、SVG、WebGL/Canvas 直接渲染文件均有状态。
3. 组合组件能够追溯到输入类型、API 和调用页面。
4. 标注、选择、RT 联动、主题、错误和首帧支撑模块已登记。
5. 当前、未启用、历史副本和截图/构建产物明确分开。
6. 每个文档和 JSON 源码路径都存在。
7. 生产代码没有从本目录 import。

## 3. 调查命令

在仓库根目录执行。

### 路由入口

```powershell
rg -n '<Route|DatasetModeGate|SpectraOnlyPage' front/src/App.tsx front/src/features/bu/routes/DatasetModeGate.tsx
```

### 直接渲染实现

```powershell
rg -n 'import \* as d3|from "three"|OrbitControls|<svg|<canvas|WebGLRenderer' front/src
```

结果要把 `features/bu-viewer` 单独归为历史，不可与当前实现合并计数。

### 当前组件消费者

```powershell
rg -n 'SpectrumChart|BuSpectrumChart|BuInteractivePlot|BuPfmbHeatmap|ThreeLcmsScene' front/src
```

### 历史目录外部引用

```powershell
$refs = rg -l '@/features/bu-viewer' front/src
$refs | Where-Object { $_ -notmatch '^front\\src\\features\\bu-viewer\\' }
```

正常结果应为空。

### JSON 语法

```powershell
Get-Content -Raw -LiteralPath 'front/Agent谱图可视化参考/组件清单.json' | ConvertFrom-Json | Out-Null
```

## 4. 更新流程

1. 先更新生产源码和测试。
2. 从路由向下确认实际消费者。
3. 反向扫描直接渲染签名，防止遗漏新图形。
4. 更新 [`组件清单.json`](./组件清单.json) 的组件、支撑模块、测试和状态。
5. 更新对应专题文档。
6. 校验 JSON 和所有 `source`/`tests` 路径。
7. 检查 `git diff`，确保没有因为维护参考库而修改生产代码。

## 5. Agent 变更边界

- 可以：新增/修改本目录内 Markdown、JSON 和将来的参考截图索引。
- 不可以：从生产源码 import 本目录内容。
- 不可以：在本目录复制一套可编译 TSX。
- 不可以：为保持文档“整洁”顺手移动现有组件。
- 不可以：把 `bu-viewer` 或 `dist` 标成生产事实来源。
- 生产组件状态发生变化时，要用 import/route 证据更新状态，不能凭文件名判断。
