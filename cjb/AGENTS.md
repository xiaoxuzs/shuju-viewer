# Viewer 项目 — Agent 说明

本文适用于本文件所在项目目录及其子目录；导入、指纹与测试的业务约束按下列引用维护。

## 工作范围与授权

- 先提供简要规划，经用户确认后执行变更；已确认的方案不重复询问。只读调查和准备可先进行，用户本轮明确指示优先于这里的一般流程约定。
- 需求、业务语义、数据范围或权限存在实质歧义时，先查证再集中询问，不猜测业务结论。可由现有代码和文档确定的实现细节，在已授权范围内处理。
- 只改本次任务相关内容，保留已有未提交改动；不顺手重构、迁移数据或清理无关文件。
- 审查或诊断不等于修复授权；修改代码不自动授权部署、发布、提交或合并 PR、删除真实数据、变更访问权限。此类操作须有明确授权，并遵守运行环境的审批要求。

## 导入与测试约束

- 保持路由、数据库、ingest 适配器、指纹算法、根路径解析之间低耦合，以窄接口协作；导入编排保持薄层，算法和测试放在各自模块，不扩张成万能 `import_jobs` 文件。
- 主业务代码禁止写死本机盘符。指纹只读取元数据，不读取文件内容；精确格式、排除项及查重口径见下方模块约定。
- `cs/` 存放能力测验、性能基准及说明，不替代 `back/tests/` 单元测试。新文档、脚本和子目录优先中文命名；需要可导入包时可使用英文包名。

## 按需阅读与验证

- 修改路径导入、指纹或查重前，阅读 [模块边界与实施顺序](cs/模块边界与实施顺序.md)。其中历史规划不构成当前执行授权。
- 影响指纹或根路径性能时，按 [性能测验约定](cs/性能测验约定.md) 验收；基准中位数目标仍为不超过 0.5 秒。
- 其他能力测验从 [cs 目录说明](cs/目录说明.md) 定位与任务相关的文档，不要求通读全部 `cs/`。
- 运行与改动相关的测试及项目要求的检查。纯指令或文档修改检查引用、事实和约束即可，不要求运行无关性能基准；通过后仅在新改动、失败或未解决风险出现时扩大验证。
- 交付说明修改、验证结果和未验证项；因规则暂停时指出具体文件及条款，区分明确要求与自己的解释。
