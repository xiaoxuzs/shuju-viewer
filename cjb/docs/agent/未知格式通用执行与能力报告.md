# 未知格式通用执行与能力报告

## 正式边界

Viewer 的 Agent 负责理解数据和提出计划，但不直接运行脚本、SQL 或前端代码。生产执行权只属于 Viewer 注册的 reader、transform、join、ZP writer、projector 和 verifier。

正式链路：

```text
Source inventory / observations
→ Agent 1 DatasetBlueprint + capability assessments
→ Agent 2 DeclarativeImportPlan
→ deterministic preflight
→ Agent 1 review
→ declarative executor
→ candidate .zp
→ Viewer staging projection / API verification
→ DatasetCapabilityReport
→ user approval
→ publish
```

## 独立模块

- `app/source_inspection/`：目录分页、类型嗅探和有界 observation；不执行导入。
- `app/declarative_ingest/`：严格计划、preflight、固定转换原语、语义 ZP 扩展；不写业务数据库。
- `app/ingest/zp/`：经验证 ZP 到 universal schema 的投影；不解析私有二进制布局。
- `app/dataset_capabilities/`：Viewer 视图目录和确定性能力报告；不调用模型。
- `app/agent_import/graph.py`：LangGraph 节点和恢复；不实现字段算法。
- `app/agent_zp/service.py`：staging、发布和真实 Viewer 门禁的薄编排。

## 两层状态

事实状态：

- `DIRECT`：源文件直接存在且已验证。
- `DERIVED`：由已注册、带版本的确定性算法得到。
- `MISSING`：源输入缺失。
- `AMBIGUOUS`：存在多个可能含义或关系，未替用户选择。
- `VIEWER_UNSUPPORTED`：数据可能存在，但 Viewer 当前没有可信 reader 或视图。

页面状态：

- `AVAILABLE`
- `PARTIAL`
- `DISABLED`

`DERIVED` 必须携带 `derivation_id`。能力报告只能由 ZP 回读与 Viewer 验证事实编译，不能直接采信模型的成功声明。

## 部分成功规则

- optional companion 缺失只关闭依赖模块。
- required identity、路径边界、源指纹变化或引用完整性失败阻止发布。
- optional 模块的失败必须进入报告，不能静默删行。
- 物理表每个字段必须被映射、参与 join，或列入 `unmapped_fields`；原始行仍保存在 `source_fields`。
- `null`、数值零和未提供是不同状态。
- target/decoy 也是三态事实：只有 `DIRECT` 才解释布尔值；`MISSING` 或 `AMBIGUOUS` 在 API 中为 `null`，未知记录仍可展示。
- FASTA 不存在时不生成蛋白序列或肽段位置。
- fragment 输入不存在时不生成来源 fragment annotation。

## LangGraph 与业务表

LangGraph graph state 只保存 Case id、状态、context revision、停止标志和错误码。PostgreSQL checkpointer 负责节点恢复；`agent_import_cases/messages/attempts/artifacts` 继续负责 UI 和审计。Case id 同时作为 LangGraph thread id。

人工问题使用 interrupt/resume；用户答案先以版本和幂等键提交到业务表，再恢复相同 thread。模型、数据库或 worker 基础设施错误不会消耗科学修复次数。

## 第一版物理范围

- entity rows：CSV/TSV/TXT、JSONL、Parquet。
- JSON、XML：第一版只允许通过 `asset_dispositions` 标记为溯源或不支持，不宣称已执行其元数据。
- companion：mzML、FASTA。
- 封闭 vendor binary：只使用已注册可信 reader，未知内容明确为 unsupported。
- 首个 canonical 竖切为 Bottom-Up；现有 Top-Down 和 spectra-only adapter 保持兼容。

## 研究与展示门禁

- Agent 1 必须把目录 inventory 分页读完；小于等于 32 个文件时逐文件运行通用 inspector，更大目录至少覆盖每类扩展名。
- 目录含 mzML 或 FASTA 时，还必须分别调用科学摘要 inspector；通用嗅探不能替代它们。
- Agent 2 获得机器可读的 canonical target 类型/shape/transform 合同和 Viewer 注册视图依赖；未注册视图只可明确报告为 `VIEWER_UNSUPPORTED`。
- 每个非输入资产 disposition 必须引用该文件自己的 observation，不能用另一个同类型文件的证据代替。
- 能力报告标记 `VALIDATED_FACTS / ENFORCED` 时才驱动页面门禁；旧数据的 `LEGACY_METADATA / ADVISORY` 报告只提示，不破坏既有页面。
