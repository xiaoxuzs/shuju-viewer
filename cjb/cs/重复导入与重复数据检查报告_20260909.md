## 3. 为什么存储指纹检查没有命中上述内容重复

- 15 个数据集中，13 个有格式正确且彼此不同的元数据指纹；**57、58 的指纹为空**。
- 当前指纹计算使用文件相对路径、文件大小及 `mtime_ns`，不是文件内容哈希。相对目录结构或时间戳不同的副本，即便鉴定内容一致，也可能得到不同指纹。
- 当前数据库和实现使用 `(source_dataset_fingerprint, source_import_kind)` 复合唯一索引；这与 `AGENTS.md` 中“指纹作为唯一业务键”的文字约定存在差异。本次两种口径都查询了，均未发现存储指纹重复。
- 旧/新类型值 `DIA_CLIP` 与 `BU_DIA_CLIP`、`PRSM` 与 `TD_PRSM_BUNDLE` 也需要结合实际内容判断，不能仅因标签不同便认定内容不重复。
- 因此，“数据库中没有相同指纹”不能推出“没有相同鉴定或谱图数据”。本次没有修改指纹算法或唯一约束。

## 6. 比对方法和只读保证

1. 从当前后端配置加载连接目标，不启动应用，不运行 schema bootstrap、迁移、导入或会清理任务的业务辅助函数。
2. PostgreSQL 连接设置 `default_transaction_read_only=on`，逐轮使用 REPEATABLE READ；实际查询 `transaction_read_only` 确认为 `on`。各轮查询结束 rollback，不提交业务写入。
3. 跨数据集鉴定比较去除 `match_id`、`dataset_id`、`run_id`、`entity_id`，并通过关联表换成运行文件名及 peptide 序列或完整 proteoform 内容；另外排除与存储位置/缓存有关的 `detail_path`、`detail_cache`。
4. 保留所有鉴定科学字段和完整 `extra_metadata`，包含源记录身份、修饰、电荷、RT、分数、decoy 等。每个数据集只有一个 run；A/B/C 两侧 run 的文件名、分析模式、软件分别一致。
5. 对归一化后的记录使用双向 `EXCEPT ALL`，不是仅比较数量或哈希，也不会忽略重复次数。A/B/C 的双向差集均为 0。
6. 谱图/ZP 文件 SHA-256 使用 PowerShell `Get-FileHash` 实际读取；没有把业务元数据指纹替换为内容哈希。
