# Viewer 源码交付版（Windows x64）

这是保留当前业务源码、但不带已有实验数据和数据库记录的交付包。请完整复制本文件所在目录，不要只拿 `back` 和 `front`。

## 第一次运行

1. 将整个文件夹解压到本机可读写的目录，例如 `D:\Viewer`。不要在压缩包内部运行，也不要放到只读目录、网络共享目录或 `Program Files`。建议使用较短路径。
2. 双击 `check-env.bat` 检查随包运行环境。
3. 双击 `start-all.bat`（`start-delivery.bat` 是同一流程的别名）。首次会自动创建独立的 PostgreSQL 数据目录、空数据库和表结构，再启动前后端。
4. 看到 `READY` 后，在浏览器打开 <http://127.0.0.1:15173>，点击 **Upload local dataset** 自行上传。
5. 使用时保留启动窗口。结束时双击 `stop-all.bat`，或在启动窗口按 Ctrl+C，等待停止完成。不要直接强行关闭窗口。

不需要手工安装 PostgreSQL 服务，不需要用原作者的数据库，也不需要在首次启动时联网下载 Python/Node/npm 包。首次解压后，杀毒软件扫描可能使启动稍慢。

| 服务 | 交付版地址 |
| --- | --- |
| 前端 | `http://127.0.0.1:15173` |
| 后端文档 | `http://127.0.0.1:18000/docs` |
| 后端健康检查 | `http://127.0.0.1:18000/health` |
| PostgreSQL | `127.0.0.1:55432`，数据库 `Viewer_Delivery` |

这些端口与原工程常用的 5173、8000、5432 分开。全部服务只监听本机，不是互联网部署方案。端口被占用时启动器会报错，不会结束其他程序。`start-back.bat`、`start-front.bat` 供开发时分开启动使用，不要与 `start-all.bat` 重复运行。

## 数据库和数据文件

- `数据库/空库结构.sql`：从原数据库只读导出的 19 张表及相关序列、索引、约束；没有 INSERT、COPY 数据或原序列计数。唯一兼容处理是将 public schema 创建改成 `IF NOT EXISTS`。
- `shuju/`：交付时为空。上传文件、转换产物和派生索引在这里生成。
- `.runtime/postgres/`：首次启动时新建的独立数据库；交付时不存在。数据库不注册为 Windows 服务。
- `.runtime/logs/`：启动后生成的前后端及数据库日志。
- 首次应用启动可能生成框架内部的迁移版本记录，这是系统运行元信息，不是原作者的数据或导入历史。

后续启动会保留同事自己导入的数据，不会清空已有记录。备份时应先正常停止服务，再同时备份整个 `.runtime` 和 `shuju`。已经使用过的目录不要再当作“空数据包”发给别人。

## 配置和密钥：重要

`back/.env` 是基于原作者实际使用的配置制作的，不是 `.env.example` 的复制品。模型名称、服务地址、超时与 API 密钥已保留；不要用示例文件覆盖它。

为独立运行，仅适配了交付版数据库连接、数据目录、ZP worker/engine 路径、外部工具路径和原机器的路径白名单。数据库账号为交付版新建，随机密码保存在此 `.env` 中，首次初始化时自动使用。

**包内含真实 API 密钥，只能私下交付可信同事；不要上传公开仓库、公开网盘或粘贴 `.env` 到聊天中。** 调用未知格式 Agent 会联网、可能产生 API 费用，并按原功能向配置的模型服务发送任务所需的材料。正常已支持格式的上传验收没有调用这些模型。

数据库首次初始化后，不要只改 `.env` 中的数据库密码；数据库内密码不会随文件自动修改。此启动器刻意拒绝普通 5432 端口以及其他数据库名称，避免误连其他实例。

## 已随包提供

- Python 3.12.7 x64、当前后端环境的 70 个依赖包、Tcl/Tk。
- Node.js 24.14.1、pnpm 10.33.1、uv、锁文件和前端离线缓存。
- 已重新安装为普通目录的前端依赖，不依赖原机器的 pnpm 目录链接。
- PostgreSQL 18.3 的运行程序、库、共享资源和许可证，**不含原 PostgreSQL 的 data 目录**。
- ThermoRawFileParser 1.4.5 完整工具目录及许可证。
- 项目内置 ZP 引擎、PFMB Python 读取模块、Unimod 资源。
- `runtime/installers/` 下的 Python 安装程序和 VC++ x64 运行库安装程序，供系统缺少运行条件时使用。

## 可选依赖与数据边界

- 本交付包针对 Windows x64，不适用于 macOS、Linux 或 Windows ARM 原生运行。
- 新电脑如提示缺少 `VCRUNTIME` / `MSVCP` DLL，可运行 `runtime/installers/vcredist_x64.exe`。这是系统安装操作，可能需要管理员授权。不要从不可信网站下载单个 DLL。
- ThermoRawFileParser 依赖 Windows 的 .NET Framework。工具版本检查已在当前机器通过；新电脑若缺少对应 .NET 系统组件，需要启用或安装该组件。
- 原项目配置位置没有 `pfmb_bridge.exe`，未将其伪装为已包含。依赖该 bridge 自动生成 PFMB 的具体工作流仍需对应工具；已有 PFMB 的读取模块已包含。
- 原后端环境未安装 Bruker 可选 `tdfpy`，该可选读取能力未离线打包。需要时应按 `back/README.md` 安装可选依赖并配置合法的 Bruker 运行库。
- 原作者的默认 FASTA、PFMB 样例结果、RAW/mzML、ZP 等数据均未携带。默认 FASTA 路径已清空；需要蛋白序列覆盖时，同事应随数据提供相匹配的 FASTA，或自行配置 `BU_DEFAULT_FASTA_PATH`。
- 原生 mzML 加速程序不是必需项；未找到对应二进制时，原业务代码会使用 Python 路径。
- 数据目录要有写权限和足够空间，上传功能默认保留 5 GiB；转换期间还需要原始文件之外的临时及结果空间。

## 开发与排错

业务 Python 和前端源码与复制时的原工程一致；交付适配仅涉及 `.env`、启动脚本，以及 Vite 代理读取启动器传入的后端地址。不包含 `.git`、原虚拟环境、历史日志、临时运维脚本及实验数据。

首次启动失败先看 `.runtime/logs`，不要对其他 PostgreSQL 执行初始化 SQL。如果启动窗口曾被强行关闭，确认本包已经不再运行后，可在本目录运行下面的命令停止它自己的数据库，再重新启动：

```powershell
.\runtime\python\python.exe -B .\delivery.py stop-database
```

前端构建应在 `front` 目录执行，避免 Tailwind 配置的工作目录错误：

```powershell
cd front
..\runtime\node\node.exe node_modules\typescript\bin\tsc -b
..\runtime\node\node.exe node_modules\vite\bin\vite.js build
```

需要重建前端依赖时，可使用随包离线缓存（路径以实际解压位置为准），并保留普通目录布局：

```powershell
cd front
..\runtime\tools\pnpm.exe install --offline --frozen-lockfile --ignore-scripts --store-dir ..\runtime\pnpm-store --config.node-linker=hoisted --config.package-import-method=copy
```

`cs` 中的历史性能/真实数据验收脚本不自带数据，有些保留原机器示例路径；运行前应按脚本说明指定自己的数据位置。`交付工具` 中“制作副本”“导出空库”是原作者的制作记录，不是同事的启动步骤；不要在同事机器上重跑它们。

具体复制清单、排除清单和验证记录见 `交付清单/`。
