## `docs/解释文件需求.md` 逐行解释

> 这份文档定义了 `prsm.js`（PrSM 详情文件）在两种谱图来源模式下的**字段需求**：
> - **版本一**：MS1/MS2 原始谱来自 TopFD 的 `spectrum*.js`（当前查看器使用的模式之一）。
> - **版本二**：MS1/MS2 原始谱改为后端从 mzML 内存读取（mzML-memory 模式）。
>
它解释“哪些字段必须由 prsm.js 提供（鉴定解释层）”“哪些字段不必放进 prsm.js（原始谱峰数组）”，并补充在 mzML 模式下如果仍要保留“同位素包络局部视图”，需要额外提供 envelopes 信息。

---

### L1-L13：标题、写法约定与 prsm.js 入口

- **L1**：标题：`prsm.js` 文件需求。
- **L3**：本文按“字段名：是什么/用于什么”的格式逐项说明（这本身就是逐行解释的写法约定）。
- **L5-L13**：给出 prsm.js 的基本入口结构：
  - 文件顶层应该定义一个变量（示例用 `prsm_data`）
  - 其内部含 `"prsm": {...}` 主体对象

这与后端 `load_js_object` + `load_prsm_detail` 的兼容读取逻辑一致：它会从 js 外壳里解析 JSON，并允许根对象是 `{prsm:...}` 或直接就是 prsm 对象。

## 版本一：当前查看器使用的 prsm.js（L15-L121）

### L17：版本一的关键假设

- MS1/MS2 原始谱来自 TopFD 的 `spectrum*.js`，因此 prsm.js **不需要**存完整原始峰数组；
- 但必须存：
  - 谱图定位信息（ms1/ms2 ids/scans）
  - 去卷积峰（ms.peaks）
  - 匹配离子（matched_ions）
  - 序列注释/断点/质量偏移（annotated_protein.annotation.*）

### L19-L23：顶层结构字段

- `prsm_data`：入口变量名（后端从这里读整条数据）。
- `prsm`：单条 PrSM 的主体对象。

### L24-L32：prsm 顶层摘要字段

- `prsm_id`：业务编号（用于 URL、列表跳转、定位 prsm*.js 文件名）。
- `p_value/e_value/fdr`：显著性与假阳性控制指标（用于排序与展示）。
- `matched_fragment_number/matched_peak_number`：匹配统计（用于 summary 与质量判断）。

这些摘要字段在当前实现里通常会被写入 `identification_matches`（至少 e_value/fdr/matched counts），并在 detail 时与 ms_header/annotated 互相补全。

### L33-L44：`prsm.ms.ms_header`

- `spectrum_file_name`：来源谱文件名（对 mzML mapping/多 run 很关键）。
- `ms1_ids/ms1_scans`：用于定位默认 MS1。
- `ids/scans`：用于定位默认 MS2（注意 TopFD 用 `ids` 表示 MS2 ids）。
- precursor 信息：mono_mass/charge/mz
- `feature_inte`：强度

当前前端：
- TopFD JS 模式用 `ms1_ids` 与 `ids` 去请求 `/spectra/ms1/{id}`、`/spectra/ms2/{id}`；
后端：
- `prsms.py` 详情会用 ms_header 的这些字段补全输出。

### L45-L55：`prsm.ms.peaks.peak[]`

定义去卷积峰数组每条必须有哪些：

- `spec_id`：峰所属谱图 id（用于关联回 MS2）。
- `peak_id`：去卷积峰编号（用于与 spectrum 的 `envelopes[].id` 对齐，支持局部 envelope 视图）。
- `monoisotopic_mass`：中性单同位素质量（用于 fragmentation/误差等）。
- `monoisotopic_mz`：用于叠加匹配离子到原始谱峰。
- `intensity`、`charge`
- `matched_ions`：该峰匹配的理论离子列表。

对应前端：
- `MatchedPeaksTable`、`FragmentationView`、MS2 图的 matched overlay，都依赖这些字段。

### L56-L68：`matched_ions.matched_ion[]`

对每个匹配离子要求的字段：

- `ion_type`（B/Y/C/Z_DOT 等）
- `match_shift`（质量偏移匹配信息）
- `theoretical_mass`
- `ion_position/ion_display_position`（序列定位与显示）
- `ion_sort_name`（稳定 key/排序）
- `ion_left_position`（覆盖范围）
- `mass_error`、`ppm`（误差展示）

对应前端：
- `SpectrumChart` 的离子着色与标注、`MatchedPeakSpectrumPanel` 的离子 label、`FragmentationView` 的 ladder 与 error plot，都依赖 `ion_type/ion_display_position/theoretical_mass/ppm` 等。

### L69-L121：`prsm.annotated_protein` 与 `annotation.*`

核心是让前端能画 `SequenceView` 与序列覆盖：

- annotated_protein 顶层：sequence_id/proteoform_id/sequence_name/description/proteoform_mass 等
- annotation 内：
  - protein_length / first_residue_position / last_residue_position（form slice 范围）
  - annotated_seq（带修饰序列字符串）
  - residue[]（逐字绘制）
  - cleavage[]（断点括号）
  - mass_shift[]（背景块与注释）

这与当前 `front/src/features/prsm/SequenceView.tsx` 的输入结构相匹配。

## 版本二：mzML-memory 模式（L122-L230）

### L124-L141：为什么 mzML 不能替代 prsm.js 的解释字段

- mzML 只能提供原始谱峰/RT/MS level/precursor 等“谱图层”信息；
- 不能提供：
  - PrSM 业务编号
  - 统计指标
  - 去卷积峰与 matched ions
  - annotated protein/cleavage/mass shifts

因此 prsm.js 仍必须保留版本一的解释层字段。

### L143-L154：mzML 模式下 ms_header 仍需提供的定位字段

- `spectrum_file_name`：用于选择哪个 mzML 文件/run
- `ms1_scans` 与 `scans`：用 scan 定位默认 MS1/MS2
- `ms1_ids/ids`：可作为兼容字段保留
- precursor/feature_inte 等仍建议保留（因为 mzML 的 precursor 可能与鉴定使用的不完全一致）

### L155-L180：建议新增 `spectrum_map`

- 提议在 prsm.js 增加一段更明确的映射信息：
  - source_type/mzml_file/default scan/all scans/native_id 等
- 目的：当 scan 不稳定或存在歧义时，用 native_id 精确定位谱图。

当前仓库实现的 mzML-memory API 使用的是 `(dataset_id, run_id, scan_number)`；文档的 spectrum_map 可以视为“把 run_id+scan 的信息显式写进 detail 或 metadata”的未来增强方向。

### L181-L216：为何 envelopes 需要补充

- 如果不再读取 TopFD `spectrum*.js`，那么原本 spectrum 里提供的 `envelopes[]` 就不存在了；
- 但当前查看器仍想保留“点击 matched peak → 局部 isotope envelope”功能，就必须在 prsm.js（或与其强绑定的解释结构）补充 envelopes：
  - envelopes[].id 必须与 peak_id 对齐
  - mono_mass/charge/env_peaks[] 提供局部 cluster 的点

这与当前前端 `findMatchedEnvelope`/`MatchedPeakSpectrumPanel` 的数据需求一致。

### L217-L221：明确“不需要放进 prsm.js 的内容”

- MS1/MS2 原始峰数组不应放进每个 prsm.js（避免重复与巨大文件）。

### L223-L230：两个版本区别总结

- 当前版：TopFD spectrum*.js 提供原始谱峰 + envelopes；prsm.js 提供鉴定解释层。
- mzML-memory 版：mzML 提供原始谱峰；prsm.js 仍提供鉴定解释层；若要 envelope 视图则需要额外提供 envelopes。
