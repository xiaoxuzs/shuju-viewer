## `docs/添加数据说明.md` 逐行解释

> 这份文档面向“维护者/操作者”，解释如何把一套新的 TopPIC/TopFD 结果包导入到新数据库 `Universal_Viewer`。它强调 fast 模式：谱图不入库、PrSM 详情不在导入阶段全量解析，详情在前端打开时才按需读取。

---

### L1-L11：标题与核心策略

- **L1-L3**：标题与目的：导入一套新的 TopPIC/TopFD 结果包。
- **L5-L11**：明确 fast 模式策略：
  - 谱图峰不写入 PostgreSQL；
  - PrSM 详情导入时不全量解析；
  - DB 只登记路径与摘要；
  - 详情页打开时按需读取 `prsm*.js` 与 `spectrum*.js`。

这与当前后端实现一致：`identification_matches.detail_path` + `spectra.py` 读取磁盘谱图。

## 4. fast 模式导入方法（L121-L150）

- 用伪流程图说明 fast 模式做的事情：
  - 读取 proteins.js → 写 datasets/runs/proteins/proteoforms/relation/matches
  - 只登记 prsm*.js detail_path
- 明确 fast 不会读取谱图峰、不逐个打开 prsm*.js、不写入完整 ms_header/ms_peaks/annotated_protein。
- 说明详情页按需读取 detail_path，并解析 header/peaks/annotated_protein 返回前端。

## 5. 导入进库的内容（L154-L295）

该段按表解释写入内容与关键字段：

- **datasets**：写入 analysis_mode=TOP_DOWN、source_software=TopPIC_TopFD、capabilities 等。
- **runs**：写入 1 条 run（fast 模式通常单 run）。
- **proteins**：从 proteins.js 写入，extra_metadata 保存 TopPIC 来源字段与统计（示例 JSON 给出）。
- **peptides**：top-down 不写，因此为 0。
- **proteoforms**：从 compatible_proteoform 写入，fast 模式 modifications 默认 []，extra_metadata 保存来源与统计（示例 JSON 给出）。
- **protein_relation_mapping**：写 protein → proteoform 归属（entity_type=PROTEOFORM）。
- **identification_matches**：
  - fast 模式写摘要与 detail_path；
  - scan_number 在 fast 模式暂写 -1（因为不读 prsm*.js 时取不到真实 scan）；
  - extra_metadata 保存 source_cutoff/source_prsm_id 等业务字段，并标记 import_mode=fast（示例 JSON 给出）。
