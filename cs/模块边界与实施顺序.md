# 导入模块边界与兼容约束

## 模块职责

- [指纹模块](../back/app/fingerprint/dataset_metadata_fingerprint.py)：公开 API `compute_dataset_metadata_fingerprint` 返回包含 `fingerprint`、`file_count`、`elapsed_seconds` 的结果对象；不依赖 FastAPI、SQLAlchemy 或 ingest，也不发起导入。
- [根路径模块](../back/app/dataset_ingest_root/resolver.py)：将用户选择的可能多层嵌套目录 `resolve()` 后定位唯一 ingest 根目录，多个候选时报错。支持范围按现有实现和测试确定，不再假定仅 TopPIC；不实现指纹或直接写业务大表。
- [导入编排](../back/app/services/import_jobs.py)：校验策略、job 阶段、调用 planner / `ingest_universal_*`、finalize、写入 `source_root` 和指纹列、处理冲突；不内联递归扫盘、MD5 或测试代码。
- `cs/` 只组织测验和验收，调用公开 API；命名与通用实施规则见 [AGENTS.md](../AGENTS.md)。

## 指纹兼容性

- 递归 `scandir`，不跟随符号链接目录或文件，不读文件内容。
- 跳过 `.DS_Store`、`Thumbs.db`、`manifest_fast.json` 及以 `._` 开头的条目。
- 当前生产格式为 `POSIX相对路径|size|mtime_ns`，各行按字典序排序，以换行连接并按 UTF-8 编码，计算 MD5，输出 32 位小写 hex。它是元数据 manifest 指纹，不能证明文件内容相同或不同。
- 旧 `MD5-demo/fast_metadata_hash.py` 使用秒级 `st_mtime`，不是当前 `st_mtime_ns`，部分副本也不含 demo。保留“不读内容”的业务约束，不再要求两者摘要逐字相同；更改指纹格式须明确评估已有数据的兼容性。

## 查重口径差异

原业务约定是“指纹作为唯一业务键”；当前代码为非空指纹建立 `(source_dataset_fingerprint, source_import_kind)` 复合唯一索引，并按两列查重。这是待业务确认的口径差异，不能仅凭文档审计选择一方。涉及该差异时先确认全局唯一还是按导入类型唯一，再决定实现；本说明不授权改索引、迁移、重新导入或删除数据。

## 维护顺序

修改对应模块，补充有意义的回归检查；影响性能时执行 [性能测验约定](性能测验约定.md)。原文“迁入指纹模块、创建索引、删除 ZIP 全链路”的内容是一次性迁移规划，不是每次任务都要执行的步骤；如需继续其中工作，先核实现状并取得本次授权。
