# 模块边界与建议实施顺序（规划备忘）

## 模块边界（再强调）

1. **指纹模块**：只回答「这个目录当前元数据长什么样 → 一个 hex」。
2. **根路径模块**：只回答「用户选的路径 → 唯一的 ingest 根在哪」。
3. **导入编排**：只负责流程与持久化，算法委托 1 与 2。
4. **本目录 `cs/`**：只负责「怎么测、测什么算过」，不实现生产指纹算法（禁止复制 demo 长期漂移）。

## 建议顺序

1. 根路径模块 + 单测（嵌套外层目录、单根、多根报错）。
2. 指纹模块迁入 `back` + 与 demo 行为对齐的单测。
3. 数据库列与唯一索引 + 编排层接入查重。
4. 删除 ZIP 全链路并调整 job 阶段与文案。
5. 在 **`cs/`** 落地性能入口（中文文件名），配置 `VIEWER_BENCH_DATASET_ROOT` 跑 **MZ20160222DS_histone49_html**，验收 **≤ 0.5s**。

## 指纹排除项（与 demo 对齐）

- 跳过：`.DS_Store`、`Thumbs.db`、`manifest_fast.json`、以 `._` 开头的文件。
- 不跟随符号链接目录/文件。
